  скрипты, ops и документация, а также удалённые изображения. Их нельзя потерять
  или молча заменить зафиксированной копией vendor/qianqi.
- Сборщики и проверки завязаны на текущие пути. Переименование каталогов — изменение
  кода сборки и эксплуатации, а не только внешний порядок.

## Текущие границы

```text
apps/
  hub/                 # каталог проектов
  monitor/             # сборщик, API и интерфейс наблюдений
  launch/              # интерфейс подготовки и запуска
tokens/
  QIANQI/              # профиль, сайт/ресурсы и специфичные материалы токена
  IGW/
server/                # общий бэк и адаптеры обслуживания
contracts/             # общее контрактное ядро
ops/                   # установка, выпуск, резервирование
tests/                 # общие и интеграционные проверки
docs/                  # общие решения и указатели на модули
vendor/qianqi/         # неизменяемый исторический reference
.local/                # локальные данные, исследования и артефакты
```

Не создавать отдельную копию общего финансового движка для каждого токена.
src/config/db и общие тесты оставлены в корне: ими пользуются несколько приложений.
Не переносить node_modules, dist и секреты вместе с исходниками.

## Пакеты переноса

1. Снять точную карту tracked/untracked изменений rh_project, текущего reference и
   адаптера. Сохранить исходное дерево и историю; выбрать актуальные исходники для
   каждого модуля. Не коммитить неизвестные конфиги и приватные данные автоматически.
2. Перенести хаб и монитор как отдельные приложения; одновременно обновить импорты,
   npm-команды, проверки и ссылки документации. Сохранить данные монитора и путь
   запуска работающего процесса до отдельного переключения.
3. Свести актуальные QIANQI-сайт и специфичные модули в этот репозиторий, сверить с
   уже существующим адаптером и vendor. Не копировать весь старый checkout внутрь.
4. Проверить сборки сайтов, адаптер QIANQI и затронутые соседние пути. Проверить
   release manifests, ops-пути и возможность воспроизводимой сборки.
5. Обновить входную документацию. Старый checkout оставить как сохранённый источник,
   пока полнота переноса не подтверждена. Публикация и смена production-путей —
   отдельный выпуск с резервной копией и откатом.

Финансовое состояние, кошельки, журналы и ключи не часть файловой реорганизации.
Перенос исходников не переиздаёт токены и не запускает второго исполнителя.
