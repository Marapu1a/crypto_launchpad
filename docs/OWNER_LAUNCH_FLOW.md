# Запуск Short через кошелёк с серверным журналом

10.10.2026, пакет после `1801e41`. Реализован и проверен путь от формы до
регистрации production-кандидата в общей БД. Среда — частный исторический fork
Pons, блок 82000000, chain4663. Публичные отправки этим пакетом не включаются.

## Что соединено

`owner.html` → `server/owner-launch/http.mjs` → coordinator → PostgreSQL013.
Шаблон принимает USDG/Short, гибкие доли комиссий, порог билета, интервал,
минимальный фонд и веса 1–64 призовых мест. Общая проверка формы и backend —
`src/launch/template.mjs`; существующий Studio использует тот же валидатор.
Кнопка картинки подключена к прежнему загрузчику Pons, отдельного IPFS нет.

Последовательность: ShortProgram с drand adapter → FeeSplitter → PonsFeeCollector
→ PurchaseRecognition → явное пополнение executor/publisher → необходимый
USDG approve → Pons launch с симуляцией и minOut → bind → регистрация проекта,
module instance и production sender. Для тестового opening buy5USDG это девять
транзакций. Нулевое пополнение/покупка и уже достаточный allowance сокращают путь;
ненулевой недостаточный allowance может потребовать approve-reset.

Используются неизменные artifacts4663 из `production-build.mjs`, buildHash
`0x24fe240da110404159ec3b3695b4b4c1dd6a312f4dabf60e261f7880207c9ad1`.
Настройки Pons сверяются с сохранёнными economics/fee перед созданием токена.
Изменение условий останавливает проход, автоматического согласия на них нет.

## Журнал и восстановление

Перед кошельком сервер сохраняет nonce, адрес, calldata, value и ограничения gas.
На владельца допускается один незавершённый запуск; PostgreSQL session lock и
revision защищают от параллельных вкладок. Executor/publisher резервируются в
едином пространстве адресов до первой подписи, включая пересечение разных ролей.
Зарегистрированные ранее кошельки также отклоняются до deployment.

После отправки hash сверяется с сохранённым запросом. Receipt должен находиться
в канонической ветке и достигнуть finalized. Только затем доступна следующая
подпись. При повторном открытии также сверяются блоки истории и runtime-коды.
Повторное открытие зарегистрированного запуска не создаёт новый токен.

Если ответ кошелька потерялся, вставить hash из его истории и нажать «Проверить
отправку». Повтор запроса подписи разрешается только с прежними nonce и данными,
если nonce ещё не занят. Автоматически перейти на новый nonce нельзя. Если
очищен браузер, «Продолжить запуск по ID» загружает авторитетный серверный журнал.
ID следует сохранить; поиск всех запусков владельца пока не добавлен.

Revert/смена ветки/изменение economics требуют отдельного разбора. Автоматической
отмены или редактирования частично развёрнутого запуска в этом пакете нет.
Утрата DB journal у уже зарегистрированного проекта не разрешает повторный launch.
DB checksums обнаруживают несогласованность записей, но не защищают от администратора
БД; RLS не делает общую executor-роль отдельным пользователем для каждого токена.

## Среда и проверка

```powershell
npm run build
npm run test:owner-launch
```

Тест самостоятельно поднимает отдельные PostgreSQL17, in-process Hardhat4663 и
временный HTTP-сервер с `/owner.html`, подключает EIP-1193 fixture в Chromium,
затем закрывает их. Нужны зависимости, Chromium и настроенный archive RPC через
существующий `scripts/rpc-config.cjs`. Тестовые ETH/USDG получаются только на fork.
В обычный `npm run dev` этот coordinator не встроен; существующая панель4185
остаётся прежним Studio. Это проверенный интеграционный кандидат, не установленный
публичный launcher или постоянный стенд для расширения владельца.

Server-only profile задаёт owner, разные executor/publisher, anchor, внешние
runtime hashes, timing bounds, gas caps, суммы пополнения и общий native budget.
HTTP не принимает RPC, ключи, произвольные calldata или режим mainnet.
Кошелёк дополнительно проверяет hardhat instanceId. Приватный ключ владельца
серверу не передаётся. HTTP рассчитан на loopback и exact same-origin;
публиковать его без отдельной аутентификации/операторского контура нельзя.

В репетиции используются явно тестовые timing и budget: lead3600s,
clockLag/Ahead30s, finalizedLag1800s, beaconLag30s, maxGasPrice100gwei,
maxGasLimit15M, пополнения по0.001ETH, totalNativeLimit2ETH. Это не согласованные
боевые значения и не оценка стоимости реального запуска.

Сценарии: невалидная форма/immutable plan; origin и конкурирующие резервации;
потерянный ответ, пересоздание coordinator и очистка браузера; задержка finality;
полный launch/bind/registration; RLS, потеря DB session и утраченный journal.
Финальный отчёт и ограничения записываются в `.local/test-results/owner-launch-*`.

Результат: 5 сквозных сценариев PASS, 23 unit/соседних проверки PASS, 10 shared
проверок PASS, build PASS. Источники и границы:

- `.local/test-results/owner-launch-2026-10-10T15-36-16-753Z/report.json`:
  окончательный проход, runtime source hashes, блоки/транзакции только fork.
- `.local/test-results/shared-2026-10-10T15-34-55-823Z/report.json`:
  миграции001–013, RLS, роли, reader, backup/restore.
- `.local/test-results/owner-launch-2026-10-10T15-34-56-581Z/report.json`:
  сохранён неудачный промежуточный тест — второй fixture-owner не имел USDG
  для opening buy; отрицательный сценарий исправлен на openingBuy0.
