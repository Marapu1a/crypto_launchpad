# Фонд холдеров: локальный контур поступлений

Актуализация: [исправления ревью](PW_INTERIM_FIXES_20261018.md). Новый holder collector учитывает только escrow callbacks; прямой ETH изолирован. Общий append закрыт для observed funding; добавлена явная сверка и блокировка запуска PW.

18.10.2026. Основание — HEAD `a5cd33d` и текущие незакоммиченные пакеты
ETH/holder preparation. Работа изолирована от действующих IGW/QIANQI.

## Контракты

`contracts/holders/NativeHolderFeeSplitter.sol` — отдельный распределитель:
holderFund, drawFund, project. Доли задаются явно при создании; политика PW
и наблюдатель требуют 6000/2000/2000 bps. Раздельные credits, накопительное
целочисленное округление и резерв остатка. Доставка каждого направления отдельная:
отказ адреса проекта не блокирует два фонда. Повторный вход запрещён.

`NativeHolderVault.sol` — **накопительный прототип**, только приём ETH и счётчик
поступлений. У него пока нет withdrawals, rescue, upgrade или начисления прав.
**Не развёртывать с реальными средствами:** деньги нельзя будет вывести.
Финальный контракт выплат и его полномочия — следующий пакет, не скрытый default.

Контекст фонда вычисляется из projectId/chainId/token/asset. Источник каждого
контракта однократно привязывает создатель; проверяются взаимные getters.
Splitter принимает только от закреплённого collector, vault — только от splitter.
Прямой вызов fund посторонним адресом отклоняется. Принудительный ETH не считается
поступлением: наблюдатель не вычисляет доход из изменения баланса.

Это отдельная сборка `src/holders/build.mjs`. Старые контракты и manifest ETH
не изменены; тест сверяет прежний native buildHash.

## Проверка и импорт поступлений

`src/holders/funding-receipt.mjs` по запросу читает конкретные txHash/logIndex:

1. Сеть, успешный receipt, блок не раньше границы запуска, `finalized` head.
2. Канонический hash блока до и после чтений, runtime code hashes по закреплённой
   конфигурации на высоте receipt, instance и связи collector/splitter/vault/draw.
3. Доли PW и источник события Revenue; для Deposited — также совпадающее
   событие Delivered(holder lane, vault, amount) в той же транзакции.
4. Формирует стабильную идентичность chain:txHash:logIndex и нормализованное
   наблюдение с policyHash, blockHash, суммой и накопительным счётчиком.

`importHolderFunding` берёт неизменяемую fundingPolicy из БД, проводит проверку,
затем записывает наблюдение через транзакционный адаптер подготовки. Повтор не
добавляет денег, смена содержимого отклоняется. Накопительные счётчики требуют
полной последовательности событий с начала: пропуск нельзя незаметно принять.
Deposit до соответствующей revenue не создаёт доступный фонд.

В профиле с fundingPolicy синтетические `fixture-only` receipts запрещены.
Старые профили без policy остаются репетиционными; их события не переобозначаются
как подтверждённые. Профиль нельзя незаметно переключить после регистрации.

## Пределы

- Тест использует реальные receipts локальной EVM, но Pons curve/escrow — fixtures.
  Не проверялись публичный RPC, live finality или развёртывание PW.
- Наблюдение доверяет закреплённому RPC и конфигурации контракта. Replay проверяет
  структуру/счётчики сохранённых наблюдений, не доказывает блок криптографически.
- Caller обязан предоставить корректный policy с runtime hashes проверенной сборки.
  Автоматического production-манифеста, sender или сканирования истории нет.
- Новый NativeHolderCollector отделяет прямое пополнение от escrow fees.
  Доверие к происхождению средств внутри самого Pons escrow остаётся;
  сервисные платежи к этому пути не подключены.
- Нет фонового polling/rollback. Добавлена явная reconciliation всей ограниченной
  истории перед расчётом и при восстановлении; несовпадения блокируют результат.
- Допуск снимка и выплаты по-прежнему отключены; executionEnabled=false.
  Денежные пороги ETH не выбраны, контракты старых токенов не изменены.
