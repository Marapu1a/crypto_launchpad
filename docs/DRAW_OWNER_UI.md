# Локальный конструктор и публичные данные v2

11.10.2026, база709cbdc. V2 соединён с owner UI, подготовкой обслуживания,
загрузчиком общего runtime и страницей токена. QIANQI/VPS не менялись.

## Конструктор

В отдельном v2-стенде доступны Short, Monthly и оба. Short — до168 часов,
корзина до64 мест с автоматическим заполнением недостающих весов единицами.
Monthly —30 дней, одно место, gate75/25; minimumFund и резерв Next задаются
отдельно. Ползунок делит призовую часть комиссий с точностью0.01%.
В одиночном режиме она полностью идёт выбранному типу; в двойном обе доли
строго положительные. Общие ticketPurchase, fee split и получатели сохранены.

`src/launch/owner-form.mjs` валидирует копию через тот же validateDrawLaunch,
что использует сервер. Скрытые поля выключенного типа не вводятся заново,
их прежняя корректная конфигурация сохраняется. Ошибочный ввод не портит
сохранённый draft. Backend повторно проверяет конфигурацию до сохранения/подписей.
V1 не преобразуется: отдельные browser storage keys и выбор coordinator
по версии подготовленного серверного стенда, не из запроса браузера.

После deployed кнопка подготовки выполняет явный registerDeployedDraw,
сверяет журнал/владельца/ключи и возвращает `draw-runtime-config-v2`:
`enabled:false`, `allowPublicTransactions:false`.
Сама кнопка не запускает worker, не регистрирует домен и не отправляет транзакции.

## Общий runtime и сайт

Загрузчик проверяет adapter_version и policy schema соответствующей версии,
policy hash и разные ключи двух ролей. Runtime выбирает v2 worker только для
проверенной v2 policy. V1 transport health/journal formats сохранены;
старая конфигурация не принимает v2 registration. Команда `npm run start:draw -- FILE`
использует общий runtime runner; подготовленный файл остаётся выключенным.
Активация и реальные отправки не входят в этот пакет.

Публичный снимок draw-public-v2 записывается в существующую short_public_views
(историческое имя таблицы, новая миграция не нужна). В нём только разрешённые
поля, без policy, signed raw, секретов и доказательств отдельных покупок.
Чтение привязано к finalized/canonical cursor; проверяются runtime hash и
соответствие frozen budget/participants. Ошибка сохраняет предыдущий снимок
с отметкой projectionFailed, старый блок/revision не заменяет новый.

API `/api/draws` и совместимый `/api/short` возвращают отдельные карточки
включённых типов; их публичный id — module UUID с суффиксом типа.
Доступ по прежнему разрешённому Host и project RLS. На странице видны доли,
интервалы, Short basket, Monthly Current/Next, исход/обязательства и общий
счётчик начисленных билетов. Повторённый в двух карточках totalIssued — общий
объём покупок, не сумма двух разных эмиссий билетов и не число оставшихся.

## Локальный запуск

```powershell
npm run build
npm run owner:draw-rehearsal
```

Owner UI: http://127.0.0.1:4188/owner.html. Создаются отдельные временные PG,
частный fork82000000 и тестовые ключи. Старый v1-стенд4186 не переключается.
Состояние сохраняется на сервере; UI можно перезапустить с прежним owner-server.json,
пока жив исходный supervisor/fork. Это не восстановление всей среды после её остановки.

Один такой стенд имеет одну заранее подготовленную пару служебных кошельков
для одного owner launch. Для следующего независимого запуска нужны новые роли
и среда/профиль; автоматическая выдача следующего набора ключей в UI ещё не сделана.
Runtime уже принимает несколько отдельных зарегистрированных проектов.
Страница токена требует отдельно подготовленного домена/публикации снимков;
owner UI не включает её и службу автоматически.

## Проверка

`npm run test:draw-owner-stand`:5 сценариев PASS на реальном историческом
Pons fork, с локальным fixture-wallet. Через браузер выбраны оба типа,168 часов,
Monthly30 дней, доли70/30 и разные пороги. Проверены отмена без отправки,
перезапуск UI/восстановление того же запуска,10 шагов развёртывания,
выключенный export, отказ v1 loader для v2, paused runtime без отправок,
явный тестовый проход v2 и публичная страница двух фондов, отказ чужого instanceId.
Полный цикл розыгрышей проверен предыдущим DRAW_WORKER; здесь после запуска
проверяется начальный публичный снимок, без новых покупок и выплат.

Регрессия прежнего owner-стенда:4 PASS. Старые PG projection checks:4 PASS.
Прежний публичный сайт:4 PASS (Host/RLS, исход, stale/offline, XSS, mobile).
Модульные проверки:21 соседних +5 новых PASS. Production build PASS.
Новые тесты отдельно покрывают три режима формы/публичных данных, сохранность
draft при ошибке, Next, исход без победителя и отказ повреждённых снимков.

production daemon, реальные уведомления и текущие публичные Pons условия
этим пакетом не проверялись.

Следом — репетиция владельцем и эксплуатационная подготовка v2:
многопроектный service/preflight, наблюдение, резервное копирование/восстановление,
поддомены и отдельная отмашка на реальные отправки. PONS_COVERAGE остаётся
источником незакрытых возможностей базового Pons.
