# Настраиваемые розыгрыши — пакет 1

Решение владельца 08.10.2026: личный конструктор быстрых запусков с механиками
QIANQI, параметры которых можно менять. Не проектируем механику заново.
Рабочая версия Pons сохранена: commit 631c33e, tag pons-checkpoint-2026-10-08.
Это точка возврата, не декларация полного покрытия Pons.

Первый пакет — чистый модуль `src/draws/config.mjs`: проверка конфигурации,
независимый пресет и предпросмотр Short-корзины. Нет UI, on-chain контрактов,
учёта билетов, RNG, исполнения split или подключения к запуску Pons.

Запрошенные параметры: включение Short/Monthly по отдельности, покупки на билет,
доли призы/команда/обслуживание и число победителей каждого типа. Дополнительно
модель содержит интервалы, минимальные фонды, веса призов и минимальную единицу.
Точные продуктовые диапазоны ещё не утверждены; текущие проверки — технические.

Пресет QIANQI: BUY100USDG/билет; 90/5/5; Short6ч, фонд100, веса
7:4:2:1:1:1:1:1:1:1, minimumUnit5; Monthly30суток, Current100, Next100,
один победитель. Пресет не является чтением действующих настроек сети.
До отдельной поддержки актив USDG, 6 decimals; суммы хранятся строками,
денежная арифметика bigint. Доли хранятся в basis points и суммируются до10000.

Формула QIANQI: unit=floor(budget/sum(weights)); приз=unit*weight.
unit должен быть >=minimumUnit. Остаток budget-unit*sum остаётся в фонде.
Готовность предпросмотра учитывает также minimumFund и enabled.
Равные веса дают равные призы; крупные веса и хвост единиц дают убывающую корзину.
Количество мест Short ограничено 1–64 как в исходном ShortRulesEpochs.
Это максимум победителей: случайный допуск может дать меньше, вплоть до нуля.

Наследуемое поведение для следующих пакетов: допуск Short 0.8*x/(x+1), отбор
среди допущенных и случайное назначение призов; один приз на адрес; невыданные
призы сохраняются. Monthly имеет собственный gate75/25 и выбор по x/(x+1).
Эти алгоритмы ещё не перенесены в runtime нового модуля. Monthly winnerCount>1
явно отклоняется до отдельного расширения алгоритма, не имитируется Short-корзиной.

Открыто до финансового исполнения: маршрутизация призовой доли между активными
типами и месячными резервами; переключение типов после запуска; изменения правил
для новых циклов; округление split и бюджет обслуживания; несколько победителей
Monthly. Не меняем frozen циклы, не используем призовые обязательства для gas.
Отключение в модели — настройка нового экземпляра, не операция над запущенным.

Источники: vendor/qianqi commit ae4452547b7df09124af3bcb72261120725d5aba,
contracts/ShortPrizeBasket.sol, ShortOutcome.sol, ShortRulesEpochs.sol.
Дополнительно сверены read-only исходники QIANQI checkout
11a050d995f17c2c810db1fe5c4e7a3ec1190ff3 и docs/USER_RULES.md 08.10.2026.
Live конфигурация не проверялась, исходный проект не менялся.

Проверено 5 новых тестов: известные корзины100/200, равные призы и округление,
границы бюджета/64места и сохранение суммы, независимость конфигураций,
отключение Short, неверные настройки и неподдержанный Monthly.
Следующий пакет: интерфейс настройки и предпросмотра, затем отдельные алгоритмы
результатов с проверкой эквивалентности QIANQI.

## Пакет 2 — экран конструктора (08.10.2026)

Реализован отдельный `/draws.html`, ссылка с формы запуска Pons. Параметры билетов,
трёх долей комиссий, включение Short/Monthly, интервалы и фонды; Short поддерживает
равные веса или явную корзину с 1–64 местами. Предпросмотр показывает минимальный
фонд, суммы всех призовых слотов и остаток округления. Это не результат RNG.
Monthly остаётся с одним победителем; его денежный цикл ещё не моделируется.
Параметры выключенного типа сохраняются и доступны для исправления.

Черновик хранится отдельно от Pons в localStorage; экспортируется только валидная
конфигурация. Ошибки возле полей, сумма долей строго100%; невалидный черновик не
показывает прежние призы как актуальные. Кнопка пресета восстанавливает QIANQI.
Страница не отправляет финансовых запросов; проверка использует общий модуль
конфигурации. При подключении API сервер должен повторно проверять конфигурацию.

Проверки: production build; 3 новых browser сценария (корзины, export/reload,
ошибки/переключатели/порог, mobile/повреждённое хранилище); 2 соседних UI-сценария
Pons прошли. Проверен HTTP200 собранной страницы на4173. Screenshots сохранены
в `.local/test-results/draws-desktop.png` и `draws-mobile.png`.
Изменения поверх813bb77; алгоритмы и контракты QIANQI в этом пакете не менялись.
Следом — перенос и проверка алгоритма результата Short; Monthly с несколькими
победителями и маршрутизация фондов остаются отдельными задачами.

08.10.2026: упрощён ввод весов. По умолчанию задаются только крупные призы
(7:4:2), остальные места автоматически получают вес1. Старые черновики
переносятся удалением хвоста единиц; ручной режим полного списка сохранён
в дополнительных настройках. Переключение в ручной режим разворачивает корзину.
При уменьшении количества мест крупные призы не обрезаются молча: ошибка.
Экспорт по-прежнему содержит полный массив весов. Проверены 4 UI-сценария,
включая64места, миграцию/перезагрузку и переключение режимов; build прошёл.

## Пакет 3 — локальный симулятор Short, 08.10.2026

Разрешён владельцем после согласования пакета. `src/draws/short-outcome.mjs`
адаптирован из vendor/qianqi/scripts/short-outcome.cjs версииae445254; зависимости
на индексатор/снимки удалены, ABI/hash/dopusk/order/prize arithmetic сохранены.
`simulator.mjs` связывает корзину с набором адресов и положительных uint128 билетов.
Контекст разделяет тестовый проект и цикл. Список сортируется по адресу,
дубликаты/zero/неверный checksum отвергаются. До1000 участников — лимит UI-симулятора.

Экран `/draws.html`: генераторы10/100/1000, ручной список, bytes32seed, проект,
номер цикла. Показывает допуск каждого адреса, победителей, случайный слот приза,
назначенные суммы, невыданные призы, округление и остаток. Любое изменение входа
сбрасывает прежний результат. Без участников/фонда либо при выключенном Short
симуляция не проводится. Ввод и вывод симуляции существуют только в памяти страницы.

Проверка: 11unit (6корзина+5симулятор), 9UI (7конструктор+2симулятор), build PASS.
24наборa сравнения с неизменённым JS reference QIANQI:1/10/100/1000 участников,
1/10/64мест, дваseed; совпали winners/amounts/prizeIndices/admittedCount/resultHash.
Также формула допуска проверена точной рациональной арифметикой вплоть до uint128max;
проверены уникальность победителей, сохранение фонда, отсутствие допущенных,
повторяемость и разделение контекстов. UI:1000участников/64мест на390px без overflow.

Пределы: сравнение с исходным JS reference (из которого адаптирован модуль),
не независимая проверка deployed Solidity. Нет проверки честности истории покупок,
источника RNG, расходования билетов, lifecycle/freeze и денежных операций.
Seed можно менять только потому, что это лабораторный экран; реальному draw
reroll запрещён. Призовые результаты — расчёт, не выплаты и не обязательства.
Следом: независимая Solidity-сверка и модель фиксируемого цикла до денежного исполнения.
