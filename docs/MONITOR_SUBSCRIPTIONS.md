# Pattern Watcher: подписка и оплата ETH

19.10.2026. Реализован локальный пакет; реальный приём средств не включён.
Получатель явно утверждён владельцем:
`0x098afA6731239a00CE0aff669aaefD16b7C72114`.
Не смешивать платежи сервиса с creator fees токена или holder/draw accounting.

## Согласованная модель

- Токены и их обзор бесплатны. Вкладка «Кошельки» целиком — подписка.
- Решение владельца 19.10.2026: на старте продаём только «Кошельки».
  Уведомления не входят в текущий тариф; явно указываем это до оплаты на EN/中文/RU.
  Их будущий выпуск не блокирует запуск оплаты за работающие кошельки.
- День (24 часа) $1, неделя (7 дней) $4, месяц (30 дней) $10.
- Только native ETH в Robinhood Chain 4663; газ отдельно.
- Курс фиксируется сервером при создании счёта на 600 секунд. Источник —
  [Coinbase ETH/USD spot](https://docs.cdp.coinbase.com/coinbase-app/track-apis/prices).
  Кеш курса не старше 30 секунд; при ошибке новый счёт не создаётся.
- Сумма считается целочисленно, с округлением вверх до wei. Повторный клик
  для того же кошелька/тарифа возвращает действующий счёт под PostgreSQL-lock.
- Подписка начинается после finalized подтверждения. Продление добавляет срок
  к max(текущий срок, текущее серверное время), без автосписаний.
- Скидка PW пока не действует: порог холдинга не выбран.

## Реализовано

`server/monitor-billing/core.mjs`: одноразовый nonce и подпись кошелька,
сессии с хешированным токеном, счета, подтверждение и сроки доступа.
Поддерживаются EOA-подписи; smart-contract wallets пока не поддерживаются.
Сообщение входа привязано к домену/URI/chain/nonce/сроку. Сам вход не оплачивает сервис.

Платёж — обычная native-транзакция на получателя, с идентификатором счёта в data.
Проверяются chain, отправитель, получатель, data, точная сумма, успешный receipt,
canonical block hash и finalized height. Один и тот же платёж не продлевает доступ
повторно. Одновременные подтверждения и продления сериализуются по кошельку.

Транзакция с timestamp блока в пределах срока принимается и после истечения
таймера, когда наступит finality. Поздняя/неверная сумма/revert получает review,
не исчезает и не открывает доступ автоматически. Повторный перевод по уже
использованному счёту записывается в payment_attempts как duplicate для разбора.
Автоматических возвратов и ручной выдачи доступа через публичный API нет.

`http.mjs`: HttpOnly/Secure/SameSite=Strict cookie, проверки Host/Origin,
лимит тела/частоты POST, серверная проверка доступа к `/api/wallet` и
`/api/active-wallets`. Публичный `/api/status` не отдаёт walletActivity, включая
вложенные интервалы. Доступ владельца проекта требует той же криптографической
авторизации; по одному переданному адресу доступа нет.

`access.js`: три языка, выбор периода, точная сумма/получатель/курс/таймер,
подтверждение в Ethereum-кошельке, переключение сети, история счетов,
проверка по хешу после закрытия вкладки, выход и скрытие приватной вкладки.
При изменении аккаунта сессия сбрасывается. Без подписки — явно обозначенный пример.
Платежи в browser-тестах синтетические; реальных отправок не было.

Daemon повторно проверяет до пяти pending-счетов за проход, не чаще пяти минут
на счёт в первые сутки. Далее проверка по кнопке; RPC ограничен persistent budget.
Уведомления об активности кошельков, Telegram/Web Push и серверные watchlists
в этот платёжный пакет не входят и ещё не реализованы. Пока они и источник
истории не готовы, paymentsEnabled=false. Вопрос владельцу о возможности
продавать только кошельки закрыт решением владельца: уведомления исключены из
стартового тарифа. Блокером включения оплаты остаётся доступность истории Pons.
