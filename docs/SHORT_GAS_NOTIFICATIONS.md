# Ожидание газа и Telegram

Дата: 10.10.2026. Реализация для Short runtime; QIANQI не изменён.

Нехватка ETH переводит текущую операцию в `waiting/native-balance`.
Процесс остаётся жив, остальные проекты обслуживаются независимо. Состояние
сохраняется в PostgreSQL отдельно для executor и publisher. После ручного
пополнения очередной проход автоматически продолжает работу. Если транзакция
уже подписана, сохраняются её raw/hash/nonce — новая вместо неё не создаётся.

Проверяется ближайшая операция: estimateGas +20%, текущая цена газа и
зафиксированный nativeFloor. Это не прогноз стоимости полного розыгрыша.
INSUFFICIENT_FUNDS при оценке или отправке также означает ожидание; при
недоступной оценке уведомление явно не обещает точную сумму пополнения.
Другие ошибки не маскируются как нехватка газа. Автообмена и автопополнения нет.

## Уведомления

Отдельный процесс читает проверенные журналы включённых проектов. Telegram
не входит в финансовый цикл: его недоступность не останавливает worker.
Сообщение содержит проект, токен, роль, адрес пополнения, баланс и известную
сумму нехватки. Первое сообщение сразу при наблюдении ожидания, напоминание
через 6 часов; после возобновления отправок — одно сообщение о восстановлении.
Это не подтверждение завершения розыгрыша. Короткое ожидание между опросами
может не попасть в Telegram. Ошибка чтения не считается восстановлением.

Запуск после отдельной настройки: `npm run start:short-notify -- /absolute/runtime.json`.
В существующий runtime config добавляется:

```json
{
 "notifications": {
  "tokenFile": "/private/telegram-token.txt",
  "chatFile": "/private/telegram-chat.txt",
  "stateFile": "/private/gas-notifications.json",
  "intervalMs": 30000,
  "reminderMs": 21600000
 }
}
```

Файлы token/chat — отдельные приватные файлы, как databaseFile; не коммитить.
Наблюдатель использует существующую роль БД lp_executor, проверяет policy/state
checksums и привязку проекта; ключи подписи и RPC ему не нужны.
Состояние уведомлений должно сохраняться между перезапусками. Не запускать
несколько наблюдателей с разными stateFile для одного набора проектов.
При аварийном завершении может остаться `.lock`: убедиться, что прежний процесс
остановлен, затем удалить только этот lock. Он не блокирует финансовый worker.
При сбое после приёма сообщения Telegram, но до сохранения локального состояния,
возможен повтор сообщения. Абсолютная exactly-once доставка не заявляется.

## Проверка и границы

Unit: оба кошелька, недоступная оценка, потеря баланса при отправке, восстановление
того же signed intent, дедупликация, напоминание, ошибки Telegram, блокировка
конкурентного наблюдателя. Telegram transport тестируется подменой HTTP.
Интеграция: изолированные PostgreSQL и модель цепочки, два токена; обнуление
executor/publisher одного проекта, продолжение второго, чтение журналов
наблюдателем и продолжение после пополнения.

Реальные сообщения, установка службы и VPS activation в этот пакет не входят.
Перед включением нужно подключить приватные Telegram файлы и проверить доставку.

Результат: 20 unit и 9 интеграционных сценариев PASS. Локальный отчёт:
`.local/test-results/production-worker-2026-10-10T17-50-41-872Z/report.json`.
