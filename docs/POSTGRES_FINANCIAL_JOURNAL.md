# Финансовый журнал PostgreSQL — локальный транспорт

09.10.2026, пакет поверх `5c5b3fb`. Код:
`server/shared/financial-journal.mjs`, миграция `005_financial_journal.sql`.
Используется прежний `src/worker/journal.mjs::advanceTransaction` без изменения
его алгоритма отправки и проверки receipt.

Это перенос долговечного **транзакционного журнала**, не переключение целого
Short worker. Новый исполнитель принимает одну уже выбранную внутренним caller
операцию, сохраняет подпись, отправляет и восстанавливает её результат.
Планировщик fee flow/draw/RNG, snapshots и финансовые правила пока остаются в
прежнем worker. У нового транспорта нет публичного HTTP endpoint.

## Изоляция

Перед миграцией администратор создаёт `lp_executor LOGIN NOSUPERUSER NOBYPASSRLS`
и отдельно назначает аутентификацию. Runtime требует именно эту роль.
Обычные `lp_api`, `lp_jobs`, `lp_ingest` не получают доступа к подписанным байтам.

`financial_executors` связывает project/module, отдельный sender, instance fork
и неизменную конфигурацию. Уникальность `(local_instance,sender)` запрещает
использовать один кошелёк для двух зарегистрированных исполнителей этого fork.
Это не блокирует внешнего пользователя того же приватного ключа: ключ должен
оставаться выделенным процессу. Ключи в таблицах не хранятся.

`financial_operations` хранит стабильный operation ID, точный план, подписанное
намерение с raw transaction, nonce/hash и итоговый receipt. Project/module есть
во всех ключах/FK, включён FORCE RLS. Подпись и исходный план нельзя обновлять
runtime-ролью. Разрешён UPDATE только статуса/результата; DELETE не выдан.
Есть уникальность nonce, tx hash и не более одной prepared-операции на модуль.

Как в предыдущих пакетах, RLS защищает от ошибочного scope/query, но одна общая
роль сама может выбрать scope другого проекта. Изоляция скомпрометированных
финансовых процессов по DB credentials ещё не реализована. Раздельные реальные
ключи/службы и production-доступы остаются отдельным эксплуатационным этапом.

## Привязки и повторы

Регистрация проверяет module.program, chain31337, localhost fork4663, instance,
anchor и runtime hash целевого контракта. Разрешены только настроенные selectors
этого контракта, нулевая native value и заданные gas/balance limits.
Это **проверка транспорта**, не всей экономической семантики calldata:
выбор суммы, получателя/цикла и бизнес-условий принадлежит доверенному planner.
Текущий профиль рассчитан на один целевой контракт модуля, не на всю цепочку
collector/splitter/program/adapter многоконтрактного worker.

`advanceFinancialOperation` получает operation ID для **одного бизнес-действия**.
Тот же ID с изменённым планом/действием отклоняется. Caller обязан сохранять тот
же ID при повторе: новый ID после успеха означает новое действие, а не retry.

Порядок выполнения:

1. Session advisory lock исключает второго исполнителя модуля. Другая попытка
   возвращает busy; другой проект продолжает работать со своим кошельком.
2. Подпись и весь план сохраняются отдельным закоммиченным INSERT **до broadcast**.
   Ошибка сохранения запрещает отправку. Неопределённый исход записи разрешается
   повторным чтением того же operation ID.
3. После обрыва используются прежние raw bytes, nonce и hash. Если receipt уже
   существует, он проверяется и фиксируется; новый платёж не создаётся.
4. Receipt сохраняется отдельным атомарным UPDATE. Повтор подтверждённого ID
   возвращает сохранённый результат после проверки канонической ветки.

Обычная транзакционная DB-блокировка здесь недостаточна: она исчезла бы после
первого обязательного commit. Session lock держится через commit и RPC. При
смерти процесса PostgreSQL освобождает его автоматически. При потере DB-сессии
исполнитель прекращает работу; listener ошибки не даёт процессу аварийно
упасть от необработанного события. Перед broadcast выполняется проверка сессии.
Если связь оборвётся непосредственно после этой проверки, уже сохранённые
одинаковые signed bytes всё равно не могут создать две разные nonce-транзакции.

Подготовленная операция блокирует создание другой для этого модуля. Занятый
чужой транзакцией nonce не заменяется. Revert записывается и блокирует следующие
действия исполнителя; другой проект продолжает работу. При reorg подтверждённой
истории — остановка, без replacement/reroll. Автоматического сброса нет.

## Проверки

`npm run test:shared:financial` поднимает отдельный PostgreSQL. Требуется уже
работающий localhost fork на 127.0.0.1:8545; тест не сбрасывает его. Два собственных
TestUSDG и JournalPayout выполняют реальные **локальные** ERC20-переводы с двух
случайных выделенных кошельков. Это тестовые payout-контракты, не полный Pons draw.

Проверяются отсутствие доступа API/jobs, неправильный target/signer/config,
изоляция одинаковых operation ID двух проектов и запрет изменения retry payload.
Дочерний процесс действительно завершается после durable prepare; подпись
сохраняется, блокировка освобождается, родитель продолжает с тем же hash.
Эфемерный тестовый ключ передаётся дочернему процессу через IPC, не файл/argv/log.

Также проверяются потеря ответа broadcast, сбой перед записью receipt, отказ
INSERT, prepared-operation barrier, принудительный обрыв **тестовой** DB-сессии,
revert, независимость второго проекта, reorg halt и pg_dump/pg_restore журнала
с сохранением ACL/RLS. Сумма перевода и счётчик вызовов доказывают отсутствие
повторной выплаты после восстановления.

## Границы следующего этапа

Пока нет полного DB-backed Short worker, постоянной службы, production finality,
замены nonce/fee bump, ключевого хранилища или mainnet sends. Подписанные данные
остаются чувствительным содержимым БД/backup и не публикуются в документации.
Restore проверен на точной копии; **устаревший backup нельзя автоматически
активировать** без сверки receipt/nonce/операций с цепочкой: в нём могут отсутствовать
уже выполненные действия. Процедура такой сверки и handoff ещё не реализованы.

Следующий предлагаемый пакет — подключить этот транспорт к полному локальному
worker: стабильные ID шагов, привязки всех его контрактов, долговечные ссылки
на cycle/snapshot/RNG и сквозная репетиция восстановления. QIANQI не переключался.
