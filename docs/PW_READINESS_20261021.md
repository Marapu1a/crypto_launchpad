## Что мешает объявить готовность к реальному выпуску

1. Серверный PW release старый и не содержит последний общий пакет RPC.
   Нужна новая проверенная сборка PW, а не включение старой owner-console.
2. Кандидат PW использует отдельный root-owned бюджет
   `/etc/crypto-launchpad/pw/rpc-budget.json`: 10,000 запросов / 24 часа,
   интервал 100 ms. Основной Pons host использует
   `/var/lib/crypto-launchpad/pons-preflight/budget.json`: 2,000 / час,
   интервал 150 ms. Это разные счётчики; требуется согласованная конфигурация
   operator/runtime и корректные владельцы файлов. Ограничение нового кода
   запрещает чужому UID незаметно перезаписывать файл бюджета.
3. Production holder admission нельзя считать готовым: preparation намеренно
   оставляет `snapshotSemantics=unverified`, payoutMode/excludedAddresses/
   gasCostLimit незаполненными; release admission/finality поля паспорта пусты.
   Это не отсутствие проверенной логики, а отсутствие окончательной привязки
   к реальному токену/операционному профилю. Адрес curve/runtime hash появляются
   после выпуска; до включения обслуживания их нужно разрешить и проверить.
4. Текущие балансы, canLaunch, finalized anchor и live quote в этой проверке
   не обновлялись. Показания 19 октября не выдаём за актуальные. Пополнение
   служебных ролей и подключение signer остаются отдельными действиями запуска.
5. README и текст правил очищены от обещания платного доступа. Старое поле
   `servicePayments` в подготовительном JSON уже `inThisPackage=false`,
   но хранит исторические периоды; его изменение требует пересборки/сверки
   fingerprint, а не незаметного редактирования уже подготовленного профиля.
