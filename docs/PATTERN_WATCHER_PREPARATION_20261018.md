## Результат

Неисполняемый [профиль](../tokens/PatternWatcher/preparation.json) фиксирует
месячную периодичность обеих механик, purchase tickets для розыгрыша, накопление
мелких выплат держателям и отсутствие выкупа/сжигания в v1. Это не launch config:
нет подписантов, адресов фондов, salt, production ID или разрешения исполнения.

Открытые суммы и проценты — null. Порог IGW 10 USDG и минимум 50 USDG сохранены
только как исходный пример: нельзя переносить суммы, пока не выбрана валюта пары.
Согласовано 2592000 секунд: первый срок от запуска токена, последующие от завершения
прошлого цикла. Реализация: [месячный розыгрыш IGW](IGW_MONTHLY_DRAW.md).

## Сверка IGW

Публичные GET `https://igw.qianqi.site/api/project` и `/api/draws` сохранены с
датой/URL/SHA-256 в `.local/research/pw-preparation-20261018T105431Z/`.

Снимок `/api/draws` подтверждает: Short, USDG/6 decimals, порог билета 10 USDG,
минимум фонда 50 USDG, интервал 86400 секунд, веса [1], creator fee 200 bps,
split [8000,1500,500], allocation 10000 bps в Short. Указан источник Pons API.
На момент чтения: 38 выпущенных билетов, 5 адресов, 6 учтённых покупок, цикл 0.
Это опубликованный снимок, не независимая проверка storage контракта. Контрактная
проверка помечена старой при ожидании активности; данные не выдаём за live RPC.

Обнаружено различие источников: module program в `/api/project` не совпадает с
program активного Short в `/api/draws`. Не брать общий module program автоматически
как адрес розыгрыша. В этом пакете ничего не исправлялось на сервере.

Код:
- [ledger](../src/tickets/ledger.mjs): накопление трат, целые билеты и денежный остаток;
  duplicate candidate ID отклоняется, использованные попытки учитываются отдельно.
- [ShortOutcome](../src/draws/short-outcome.mjs): допуск адреса по числу попыток,
  затем порядок участников и призов. При n билетах вероятность допуска 0.8*n/(n+1).
  Это НЕ прямая лотерея с весом баланса и НЕ гарантия победителя каждый месяц.
- [ShortProgram](../contracts/production/ShortProgram.sol): фиксированные rules
  1/4/5/1/1, замороженные участники, RNG, учёт потреблённых попыток, отдельные
  обязательства победителям, невыплаченный призовой остаток остаётся в фонде.
- [MonthlyProgram](../contracts/production/MonthlyProgram.sol): другой outcome,
  отдельный резерв следующего цикла. Название Monthly не делает его заменой IGW.

## Что мешает собрать запуск без доработки

1. Новый режим v3 реализован отдельно от прежних профилей; ограничение v2 до 7 суток
   сохранено. См. [реализацию и границы](IGW_MONTHLY_DRAW.md).
2. [launch template](../src/launch/template.mjs) и конфигурация draw привязаны к USDG.
   Выбор ETH для токена потребует адаптации asset/decimals/threshold/collector,
   а не одной замены адреса. Оплата сервиса ETH не обязывает пару токена быть ETH.
3. Существующий split prizes/team/operations не содержит самостоятельного фонда
   держателей. Нельзя переименовать team в holders и считать модуль готовым.
4. Нет завершённого модуля holder snapshots/entitlements/carry/payouts и проверенной
   политики исключений. Нет основания включать финансовое исполнение.

## Граница нового модуля

Независимый модуль экземпляра получает только выделенные holder funds. Стадии:
candidate snapshot → accepted snapshot → рассчитанные права → зарезервированные
суммы → выплаты/перенос. В snapshot сохранять исходные страницы, время, версию
политики, полный список, исключения и контрольные суммы. Неполный снимок не допускается.

Round ID + wallet + asset уникальны; начисление нельзя повторить после рестарта.
Статусы отправки prepared/submitted/confirmed/failed/unknown различать; unknown
сначала сверяется, не создаёт новый перевод. Мелкие суммы остаются долгом адреса.
Долги не увеличивают доступный фонд следующего раунда. Фонды розыгрыша и держателей
не могут тратить резерв друг друга. Общая библиотека, без if token == PatternWatcher.
