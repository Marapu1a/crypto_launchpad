# RPC: нагрузка при отсутствии торговли

Проверено 13.10.2026 около 12:14–12:23 UTC. Локальный HEAD e3585b6 + рабочее
дерево. Сервер: фактические systemd/config и journal; сумма счёта не сверена
с закрытым кабинетом QuickNode. Это аудит частоты и путей, не биллинг по методам.

## Подтверждено

  За 08:00–09:00 UTC журнал содержит 227 завершённых проходов. Все с full replay;
  replay сам по себе CPU, а не RPC. persistent-buy-indexer.cjs отдельно выполняет
  canonicality/chain/finalized, scan, reward/public observations.
- QIANQI financial config pollSeconds=10, worker сейчас failed. Дополнительные
  циклы исполнения и индексирования нельзя считать одним RPC-запросом.
- IGW draw runtime intervalMs=15000, concurrency=2. runtimePass читает минимум
  два баланса, затем worker. После успешного прохода publishShortView строит
  снимок заново. draw-projection: 4 чтения блоков, code и 5 методов программы
  на включённый Short, дополнительные чтения при существующем draw/кошельках.
  Это вызовы уровня провайдера, не измеренное число тарифицируемых HTTP/RPC.
- projectWallets читает consumedThrough для каждого участника; при cycle>0 ещё
  rewards. Кэш sharedScanProvider ограничен одним проходом и raw scan.
- qianqi-api: RH_INDEXER_CONFIG отсутствует, standby. qianqi-stage-api --standby.
  Sandbox check failed, не работающий второй collector. Старые monitor timers
  читают API/состояния; наличие службы не доказывает платный RPC-трафик.
- Pons monitor не использует QuickNode. Публичные сайты читают сохранённые API
  snapshots, не запускают финансовый проход на каждого посетителя.

## Применено на сервере

Создан /etc/systemd/system/qianqi-public-indexer.service.d/zzzz-economy-cadence.conf:

```ini
[Service]
Environment=RH_INDEXER_POLL_MS=60000
```

Выполнены daemon-reload и restart только read-only индексатора. is-active=active,
в /proc/MainPID/environ подтверждено RH_INDEXER_POLL_MS=60000. Финансовый worker
остался failed, отправки не возобновлялись. RPC endpoint не менялся; TLS-инцидент
эта настройка не исправляет. Catch-up по существующему коду остаётся без паузы;
задержка применяется к догнавшему индексатору и повторным ошибкам. maxAge120с
не расширяли. Повышенная нагрузка catch-up после простоя остаётся ограничением.

Откат: удалить только этот override, daemon-reload, restart read-only индексатора.
Других конфигов, credential-файлов, кошельков и journals не изменяли.

## Следующий пакет экономии (ещё не реализован)

1. Разделить дешёвую проверку новых событий и полный финансовый/public проход.
   Тихий режим: проверка курсора/событий раз в 5 минут, все блоки от checkpoint.
   Не определять тишину только по продажам: прямое пополнение фонда, наступление
   срока draw, pending receipt/RNG/claim требуют отдельного расписания.
2. При новых событиях либо незавершённой операции ускоряться до 15–30 секунд.
   Снимок сайта перестраивать по изменению состояния, хранить отдельно timestamp
   данных и heartbeat проверки. Не выдавать старый снимок за новую проверку.
3. Ошибки провайдера: backoff 1/2/5/10 минут с jitter; последняя успешная проверка
   и ошибка видны, а ожидание следующей попытки не считается остановкой процесса.
4. Счётчики RPC по службе/методу/успеху, без URL и адресных параметров. Кредиты и
   цена зависят от провайдера и тарифного веса, не равны числу запросов.
5. Кэш подтверждённых trace/receipt по tx+blockHash, проверка canonicality при
   использовании; никакого кэша nonce/газовых оценок перед подписью.

227 проходов/час против 12 проверок/час — на 94.7% меньше именно проходов при
пятиминутной схеме, не обещание такого же сокращения счёта. Полный расход можно
подтвердить только измерениями/usage провайдера. Новые платные тарифы не включены.

## Локальный пакет адаптивной частоты — 13.10.2026

В коде IGW добавлен opt-in `economy: true` в runtime config. После трёх
последовательных waiting/conditions без operation/alerts пауза 300 секунд.
Это пока реже выполняемый полный проход, не отдельный дешёвый детектор событий.
Pending/finality/RNG/catch-up и неизвестные причины сохраняют intervalMs.
Если все проекты blocked/paused, backoff 60/120/300/600 секунд с ограниченным
jitter. В смешанном runtime активный проект сохраняет быстрый общий цикл;
отдельное расписание каждого проекта ещё не реализовано.

Health содержит schedule.mode/delayMs и учитывает запланированную паузу при
определении остановки процесса. Ошибки blocked/alerts не скрываются. Публичная
свежесть снимка остаётся прежней: проверка раз в пять минут может показывать
старый Last verified; heartbeat не подменяет время данных.

IGW health.rpc: накопительные за жизнь процесса requests/errors по методу,
общие для primary/trace provider, включая projection. Ошибки транспорта и
JSON-RPC учитываются; повторные попытки внутри HTTP transport могут не быть
отдельными вызовами _send. Это не счётчик биллинговых credits.

QIANQI indexer: backoff ошибок 60/120/300/600 секунд; успешное выполнение
сбрасывает серию. Catch-up и успешная штатная частота не менялись. health.rpc
содержит только последний дочерний проход (не накопительную сумму). Фатальные
storage/lock ошибки по-прежнему требуют внимания и не ретраятся автоматически.
Финансовый worker QIANQI в этот кодовый пакет не входил.

сброс ошибок, health, graceful drain, конфигурация, реальный localhost HTTP RPC
