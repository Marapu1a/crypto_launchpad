07.10.2026. Статус: форма и локальный путь запуска работают; полная базовая
версия ещё не закрыта. Матрица и остаток — [PONS_COVERAGE](PONS_COVERAGE.md).

## Реализация

- Vite + JavaScript modules + ethers. Runtime отдельно от `vendor/qianqi`.
- Форма Identity → Economics → Review; живое чтение настроек Pons, 71 кандидат
  ERC20 с проверкой approval плюс ETH, настраиваемые комиссии и получатели.
- Direct launch и atomic opening buy; точный ERC20 approve; Holders continuation.
- Стабильный salt, ненулевой economics pin, две симуляции защищённой покупки.
- Черновик, экспорт и локальный архив; журнал сохраняется до отправки, содержит
  account/nonce/request/hash/результат и идентификатор конкретного fork.
- Неизвестный исход не повторяется; восстановление сверяет содержимое транзакции.
  Старый журнал после перезапуска fork не принимается за актуальный.

## Найденные ограничения стенда

Обновление 07.10.2026, 16:56 UTC: владелец предоставил Alchemy endpoint через
локальный файл. `scripts/check-rpc.mjs` прошёл **8/8** проверок, включая исторические
code/call/storage/nonce/balance блока 82616126. На отдельном fork порта 8546
через этот endpoint повторены **13/13** интеграционных сценариев на том же
историческом блоке. Проверка выполнена без сброса работающего стенда на 8545;
временный процесс после тестов остановлен.

Evidence: `.local/test-results/rpc-check-2026-10-07T16-54-49-767Z.json`,
`configured-fork-2026-10-07T16-55-47-346Z.json`,
`pons-fork-2026-10-07T16-55-52-176Z.json`.
URL/ключ в отчёты не включены. Для проверенного блока endpoint подходит;
полнота архива за всю историю и лимиты длительной нагрузки не проверялись.
Текущий процесс 8545 автоматически не переключается; следующий `npm run fork`
возьмёт endpoint из `.local/config/pons-rpc.txt` (если env не переопределяет его).

Первый успешный fork-прогон (6/6) сохранён отдельно. Позже тот же стенд перестал
получать состояние исходного блока: public RPC вернул `historical state ... is
not available` для новых предсказанных адресов. Неуспешный прогон сохранён в
`pons-fork-2026-10-07T16-32-13-116Z.json`, не удалён и не переименован в PASS.
После явного reset на свежий блок прошли все 13 сценариев.

Свежий fork пригоден для текущей проверки, но гарантированная повторяемость
на том же блоке требует archive RPC. При наличии такого endpoint его можно
передать серверному скрипту через `PONS_ARCHIVE_RPC`; URL с ключом не выводится
в manifest. Автоматического reset рабочего стенда нет, поскольку он сбрасывает
локально созданные токены и обесценивает сохранённый журнал.

На границе fork Hardhat вернул ошибку определения hardfork для chain 4663 даже
при заданной истории. Стартовый скрипт добывает один локальный блок и дальнейшие
numeric reads идут по нему. Это настройка тестового исполнения, не утверждение
об истории хардфорков реальной сети.
