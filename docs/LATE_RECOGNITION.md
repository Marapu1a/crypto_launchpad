# Позднее начисление билетов — локальный пакет 08.10.2026

Пакет переносит семантику QIANQI из `ae445254`: неизменная исходная покупка,
отдельная позиция начисления, неизменный frozen snapshot, повтор без второго
начисления. Это локальная инфраструктура подтверждений, не поддержка всех роутеров.

## Поток

1. Scanner сохраняет исходную транзакцию, receipt и решение. Неподдержанный прямым
   декодером маршрут помечается `WAITING_RECOGNITION`.
2. Профиль с recognition фиксирует отдельный source, publisher, instanceId,
   runtime hash и adapter `local-verified-curve-v1`. Контракт
   `LocalPurchaseRecognition` работает только на chainId 31337.
3. Пакет JSON содержит `schema: launchpad-local-recognition-v1`, `profileHash`
   (digest полного профиля) и массив `candidates` (candidateId исходных событий).
   Хеш пакета — `0x` + SHA256 его JSON.stringify, порядок ключей сохраняется.
   В пакете нет доверенных сумм или назначаемых вручную получателей.
4. Publisher вызывает `confirm(bundleHash, count)`. Source допускает 1–50
   кандидатов и отклоняет повтор того же хеша. Подпись publisher сама по себе
   не доказывает покупку.
5. Scanner загружает `<bundleHash>.json` из явно заданного каталога (до 1 MiB),
   сверяет хеш, событие, calldata, source/runtime, publisher, instanceId и профиль.
   Исходная покупка должна быть из более раннего блока и иметь однозначные
   сохранённые свидетельства. Обычный распознаватель независимо проверяет маршрут,
   плательщика, получателя, переводы, сумму и возврат. Непроверенная покупка
   останавливает обработку пакета — автоматически доверять её статусу нельзя.
6. Производное событие получает `creditedAt` блока/транзакции/лога подтверждения.
   Оригинальная запись не меняется. Snapshot отбирает события по позиции начисления,
   а не исходной покупки; остатки пересчитываются с учётом доступных к cutoff покупок.
7. Другая доставка той же покупки не меняет первое начисление. Пакет и подтверждение
   сохраняются вместе с состоянием; перезапуск не требует исходного файла пакета.

Пример: 6 USDG распознаны сразу, ещё 4 USDG ожидают подтверждения. До подтверждения
билетов нет, после него есть один. Если состав розыгрыша уже заморожен, этот билет
доступен следующему составу, а не добавляется в предыдущий.

## Локальная проверка и использование

`createProfile(..., { recognition: { source, publisher, instanceId,
adapter: 'local-verified-curve-v1', deferDirectBuys: false }, ... })`
получает runtime hash из локальной сети и проверяет bindings. Это доверенная
настройка оператора локального теста. Менять recognition существующего профиля
нельзя: несовпадение профиля остановит загрузку состояния.

`deferDirectBuys: true` — явный режим репетиции: прямые покупки, которые уже
распознаёт декодер, намеренно ожидают подтверждения; opening buy остаётся обычным.
Так проверяем задержку на настоящей покупке Pons, не выдавая её за покрытие
неизвестного агрегатора. Для обычного распознавания параметр задаётся false.

Scan с новыми подтверждениями:

```
node scripts/index-tickets.mjs profile.json state.json cutoffBlock - bundleDirectory
```

API: `scanTickets(provider, profile, statePath, cutoff, { bundleDirectory })`.
Файлы профиля, состояния и пакетов держим в `.local/`. Не публикуем реальные
отправки и production-конфигурацию. Автоматического publisher пока нет.

## Проверки и ограничения

- Unit: дата начисления, порог с остатком, повтор в другом пакете, неизменность
  старого cutoff, расход прежних диапазонов, перезапуск; ошибки domain/authority/
  runtime/суммы/получателя/токена/маршрута/исходного блока/пакета.
- Fork: реальный launch и direct buy, отдельный source/program, подтверждение
  контрактом; отказ чужому publisher и дублированному хешу; отсутствующий или
  испорченный файл не меняет сохранённое состояние; отдельный процесс восстанавливает
  билеты без файла пакета; повтор покупки не удваивает билет; reorg вызывает halt.
- Старые сценарии обычных билетов и Solidity freeze/settle выполняются соседями.

Не перенесён специализированный trace-adapter QIANQI для router 0x65050…,
нет поддержки новых pool/batch/native маршрутов. Они не получают билеты через
ручное указание суммы. Для них нужен отдельный проверенный adapter и свидетельства.
В отличие от production-политики QIANQI, локальный source не вводит сутки notice;
production trust, notice, finality, keeper и миграция политики — отдельная работа.
При reorg нет автоматической отмены frozen результатов: индексатор останавливается.
Checksum защищает от случайного повреждения, не от оператора с доступом к файлам/RPC.

Полная репетиция первого токена с live RNG и интервалом 24 часа пока не проведена;
этот пакет закрывает локальную проверку позднего начисления, а не весь запуск.

Результат: 8/8 unit, 7/7 fork PASS, fork block 83388335. Финальный отчёт: .local/test-results/tickets-2026-10-08T15-58-38-360Z/report.json. Последний тест намеренно оставляет свои файлы с orphaned head; это свидетельства halt, не состояние для дальнейшей репетиции. Исходный QIANQI/vendor не изменялись.
