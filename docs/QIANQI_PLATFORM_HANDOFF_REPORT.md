## Что обнаружилось на сервере и исправлено

1. Старый `ExecStartPre` запускал verifier относительно WorkingDirectory. После
   её смены индексатор не стартовал; его прежний запуск был восстановлен.
   Теперь все три runtime-службы проверяют **новый** release по закреплённому
   manifest SHA256, включая311 файлов и compiled artifact. Проверка не отключена.
2. Старый native backup искал `scripts/ops-backup.cjs` и `release.json` в
   WorkingDirectory. Проверка после переноса поймала это; писатели были
   остановлены штатным fail-closed backup. Они восстановлены, затем backup
   адаптирован к обоим форматам release. Helper извлечён из rh_project@11a050d,
   SHA256 `c260d7bbdf71134ccc8606d16940c9d25c978b532e674ad810e4cffe5229d312`.
   Helper/manifest теперь проверяются **до** остановки писателей.

Обе несовместимости устранены и повторный реальный backup прошёл с автоматическим
возобновлением служб. Старые release и исходные backup-скрипты сохранены.

## Возврат на прежний runtime

Остановить нового финансового исполнителя **до** возврата старого. Сохранить
актуальные журналы; убрать только новые `zz-launchpad.conf` у indexer/automation,
перечитать systemd, запустить прежний indexer и затем automation. В nginx вернуть
upstream8789, проверить `nginx -t`, reload и API. Старый nginx сохранён в
`/var/lib/crypto-launchpad/admin/handoff-d0a6840/nginx-before.conf`.

Новый backup поддерживает также старые release и может остаться. Не удалять
старые release/доступы и **не накатывать старый state поверх новых транзакций**.
Полный финансовый rollback на production не выполнялся: проверены совместимость
состояния, staged restore и restart нового исполнителя. Возврат прежнего
индексатора фактически выполнялся при исправлении preflight.

## Оставшаяся техническая граница

Приватные журналы и scanner QIANQI пока native. Это явно переходный existing-project
adapter: финансовое исполнение и публичный API уже в платформе, полное объединение
сканирования и перевод приватного хранения в PostgreSQL ещё не выполнены.
Общие runtime-роли также не являются защитой от компрометации общей роли.
Эти ограничения не скрыты и не выдаются за закрытую полную унификацию.

Исходники и локальные проверки: [QIANQI_EXISTING_ADAPTER](QIANQI_EXISTING_ADAPTER.md).
Операторские сценарии/проверки этой сессии: `.local/handoff-2026-10-09/`.
