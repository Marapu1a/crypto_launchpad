# Локальный owner-стенд

Пакет 10.10.2026 после `e82285d`. Владелец разрешил подготовку и ручную репетицию;
реальные запуски и серверная активация требуют отдельной отмашки.

## Запуск и использование

```powershell
npm run build
npm run owner:rehearsal
```

Адрес — `http://127.0.0.1:4186/owner.html`. Прежний Studio4185 не переключается.
Нужны PostgreSQL17 (либо `PG_BIN`), зависимости и настроенный archive RPC,
который читается существующим resolver только для исторического fork.

Отдельный supervisor создаёт PostgreSQL с текущими миграциями и Hardhat4663
на блоке82000000. HTTP/RPC/БД слушают loopback. Два случайных encrypted ключа
executor/publisher создаются **до** launch profile; owner — публичный тестовый
аккаунт Hardhat. ETH и USDG доступны исключительно в локальной копии.
Службы Short, публичный сайт/DNS и серверные задачи не активируются.

В форме виден режим локального тестового кошелька. После заполнения картинки
и условий кнопка сохраняет план. Каждый следующий шаг требует отдельной кнопки
и подтверждения браузера. Отмена подтверждения ничего не отправляет. Расширение
кошелька этому режиму не нужно; его совместимость этим стендом не проверяется.

После регистрации доступна проверка ключей и выгрузка выключенного runtime.
Это подготовка, а не запуск автоматических розыгрышей. Один стенд сейчас рассчитан
на один токен: роли исполнителей закреплены в его профиле. Для независимого
нового токена создаётся отдельная среда, существующие ключи не переиспользуются.

## Ограничения отправки

`rehearsal-sign` принимает только ID сохранённого запроса. Server-side wallet
отсутствует, если HTTP handler не получил этот отдельный fixture transport.
Транспорт сверяет публичный тестовый owner, rehearsal mode, hardhat instanceId,
chain4663, profile hash, requesting-state и свободный nonce под owner DB lock.
Calldata/value/recipient/gas берутся из серверного журнала. Произвольный RPC,
calldata, recipient и параметры активации из HTTP не принимаются.

Сервер также отклоняет внешний Origin и неправильный Host. Это loopback-стенд
для доверенного компьютера, не публичный API и не production custody.
В модели finality `latest` считается finalized; это явно тестовое упрощение.

## Сохранение и перезапуск

Каждый запуск создаёт новый каталог `.local/owner-rehearsal/<timestamp>/`.
Там лежат БД, fixture credentials, профиль, `owner-server.json`, fork log и
`supervisor.json`. Ничего из этих файлов не коммитить и не использовать в бою.

Пока supervisor работает, HTTP-процесс можно перезапустить командой:

```powershell
node scripts/run-owner-rehearsal.mjs "ABSOLUTE_PATH_TO_owner-server.json"
```

Сначала должен завершиться прежний HTTP-процесс, иначе порт занят. Команда не
создаёт новые contracts, profile или ключи. После очистки браузера запуск можно
восстановить по ID из серверного журнала. Старый браузерный черновик от другого
instance показывает ID и отдельную кнопку создания нового черновика; старый
серверный журнал не удаляется.

**Перезапуск UI и перезапуск всей среды — разные вещи.** Hardhat хранит локальные
изменения цепочки в памяти. Ctrl+C у supervisor останавливает его UI/fork/БД;
файлы остаются для исследования, но восстановление цепочки после остановки
Hardhat/перезагрузки компьютера не реализовано. Нельзя подключать старую БД к
новому fork: instance binding это блокирует. Новый запуск команды создаёт новую
репетицию. Если UI был вручную перезапущен отдельно, завершить его отдельно.
Для фонового supervisor можно создать пустой файл `stop-request` в его конкретном
каталоге: в течение секунды он начнёт штатную остановку UI/fork/БД. Не создавать
этот файл в каталоге другого проекта.

## Проверка

`npm run test:owner-stand` поднимает отдельный стенд, проверяет форму, отмену,
защиту endpoint, полный fixture launch, restart UI, очистку браузера, handoff
с настоящими encrypted keys и запрет чужого instance. После теста среда закрывается.
Окончательный функциональный отчёт:
`.local/test-results/owner-stand-2026-10-10T16-47-54-249Z/report.json`:4PASS,
8 соседних owner-wallet/runtime unit PASS, build PASS. Screenshot просмотрен.
Предыдущий16-46-17 проход PASS до добавления UI для старого черновика.
Первый16-44-20 FAIL: неверное русское имя в тестовом пресете; валидатор остановил
создание плана. Исправлено на латиницу; отчёт сохранён.
После функционального прогона добавлена остановка фонового supervisor через
stop-request; её smoke-проверка фиксируется отдельно в локальных заметках.

Следом — ручной проход владельцем и отдельная репетиция подключения runtime,
страницы, мониторинга и backup/restore. Боевые timing/budget, реальный кошелёк
и разрешение на public launch остаются отдельными условиями запуска.
