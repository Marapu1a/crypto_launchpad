# Кошелёк и IPFS: первый интеграционный пакет

10.10.2026, после `daabc64`. Изменена базовая форма `/` (`src/main.mjs`).
Это проверенная локальная подпись через EIP-1193 и интерфейс публикации картинки,
ещё не production deployment всего Short template из `/launch.html`.

## Кошелёк и восстановление

В режиме Local fork на шаге «Проверка» можно выбрать «Подписывать в браузерном
кошельке». Кошелёк должен быть подключён к тому же fork31337 на127.0.0.1:8545;
проверяется не только chainId, но и hardhat instanceId. Затем подключить кошелёк
кнопкой в шапке. Использовать отдельный тестовый аккаунт с тестовыми средствами.

Approve, запуск и продолжение Holders передаются EIP-1193 provider. Приватный
ключ в backend не поступает. Перед запросом подписи сохраняются intent, nonce,
адрес, calldata, value и instanceId. Аккаунт/сеть перепроверяются перед отправкой.
Результат сравнивается с сохранённым запросом. Ответ4001 без hash считается
отказом; timeout/неизвестный результат сохраняет блокировку повторной отправки.

Если hash потерялся вместе с ответом, поле «Hash отправленной транзакции из
кошелька» позволяет восстановить единственный незавершённый шаг. Проверяется
совпадение sender, nonce, recipient, calldata и value через отдельный read RPC.
После этого «Проверить подтверждения» восстанавливает результат запуска.
Чужой hash, другой fork или неизвестная транзакция не разблокируют повтор.

Журнал остаётся в localStorage и экспортируется существующей кнопкой. Это не
серверный durable journal production worker. Удаление данных браузера не
покрывается восстановлением; параллельные вкладки не имеют общей блокировки.
Проверка receipt локальная, не production finalized admission. Для4663 отправка
из этой формы по-прежнему недоступна. WalletConnect/mobile не добавлены.

## Картинка

Выбор файла по-прежнему проверяет PNG/JPEG/WebP, размер, геометрию и декодирование
на сервере. Отдельная кнопка публикует именно выбранный файл. Неудачная загрузка
не подменяет предыдущий URI. Успех сохраняет ipfs:// в черновике, переживает reload.

Добавлен адаптер операторского Kubo. Он выключен без `LAUNCHPAD_IPFS_API`.
Для уже работающей собственной ноды можно перед запуском панели указать:

```powershell
$env:LAUNCHPAD_IPFS_API = 'http://127.0.0.1:5001'
npm run dev
```

Адаптер принимает только loopback HTTP origin из окружения сервера, не URL
пользователя. Публикация доступна только из локальной панели с совпадающим Origin.
Kubo add вызывается с pin=true, CIDv1 и raw-leaves; затем cat сравнивается с
исходными байтами и pin/ls проверяет наличие pin. Ответы ограничены размером и
таймаутом. Ошибки провайдера наружу не возвращаются. Повтор загружает те же байты;
это content-addressed операция, не финансовая транзакция.

Установка Kubo, подключение Pinata/другого аккаунта, резервное закрепление и
проверка публичной доступности ещё не выполнены. Владелец получил вопрос о
выборе сервиса. Работа адаптера проверена HTTP fixtures, не настоящей IPFS нодой.
Локальный pin сам по себе не доказывает круглосуточную доступность картинки.

Источники интерфейсов, проверены10.10.2026:
[EIP-1193](https://eips.ethereum.org/EIPS/eip-1193),
[Kubo RPC add/cat/pin](https://docs.ipfs.tech/reference/kubo/rpc/).
