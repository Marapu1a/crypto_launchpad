## Путь

После регистрации токена в `/owner.html` доступна кнопка «Проверить подготовку
обслуживания». `POST /api/owner-launch/:id/handoff` принимает пустой JSON;
передать активацию, ключи, RPC, пути файлов или чужой projectId в теле нельзя.
Сохраняются loopback Host и exact same-origin ограничения owner API.

`createRuntimeHandoff` получает от оператора executor/API pools, тот же launch
profile, базовые runtime paths, базовый домен и карту путей ключей по projectId.
Проверяет владельца, завершённый журнал, profile hash, согласованность policy,
проекта и модуля. Отдельная API-роль проверяет публичный domain allowlist.
Ключи расшифровываются только на сервере и сверяются с адресами policy;
ключ не соединяется с provider, никакие транзакции не подписываются.

UI показывает готовность двух ключей и **планируемый** URL.
Надпись о выключенном запуске относится к выгружаемой конфигурации; состояние
уже установленного процесса этим endpoint не проверяется. Наличие домена в БД
не считается проверкой DNS, HTTPS или работающего сайта. При отсутствии ключей
выгрузка недоступна; при ошибке ключа наружу не передаётся текст исключения.

Готовый JSON соответствует `short-runtime-config-v1`, содержит ровно этот проект,
его policy hash, `enabled: false` и `allowPublicTransactions: false` независимо
от исходных флагов. Параметры берутся по явному списку. Это отдельный проектный
черновик, а не замена общего реестра уже работающих токенов. Он содержит пути
к файлам credentials, но не их содержимое. Хранить его как операторский файл,
не публиковать в публичном API/репозитории. Режим и instanceId сверяются с launch
profile; текущий coordinator поддерживает только частную репетицию.

## Ключи и установка

Ключи должны быть подготовлены **до** создания контрактов: executor/publisher
закрепляются в launch profile и контрактах. Существующий operator-only
`createExecutorKeystore` создаёт encrypted keystore; для двух ролей нужны
отдельные каталоги и независимо сохранённые password files. Handoff проверяет
уже выбранные ключи и не подменяет их после deployment. Автоматическая генерация
реальных кошельков из браузера не добавлена.

Подключение сервера: создать `handoff=createRuntimeHandoff({...})` и передать
его в `ownerLaunchHttp({coordinator,defaults,handoff})`. Без настройки возвращается
понятный409; запуск формы продолжает работать. В этом пакете подключение проверено
в существующем изолированном browser/fork harness. Постоянный local owner server
и единая точка входа Studio ещё не установлены.

Handoff не пишет в БД, не меняет domain allowlist, не создаёт systemd/планировщик,
не запускает runtime и не правит существующие конфигурации. Подготовленный JSON
пока не доказывает доступность RPC/БД с будущего сервера или баланс газа.
