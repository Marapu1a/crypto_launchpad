# Картинки через Pons

10.10.2026. По решению владельца используем хранилище Pons. Kubo adapter удалён;
собственная IPFS-нода, pinning-аккаунт и ключ загрузки не нужны.

## Что проверено

Текущая [форма Pons](https://ponsfamily.com/launchpad/create) отправляет multipart
поле `image` на `POST /api/ipfs/image` и получает `{cid, uri}`.
Прямой пустой server-side POST вернул403. Тот же пустой запрос из настоящей
страницы Pons в чистом Chromium без cookies вернул400 «Choose an image to upload».
Выбор тестового PNG в штатном file input вернул200, URI и статус Pinned to IPFS.
Аккаунт, кошелёк и создание токена не требовались.

Это наблюдаемое различие между внешним запросом и запросом со страницы сайта;
точная серверная проверка Origin/Referer/Fetch-Metadata не установлена.
Поддержанный внешний upload API в просмотренной документации не найден.
403 не обходится подменой заголовков. Нет импорта пользовательских сессий,
антибот-обходов или повторов при отказе Pons.

## Реализация

В базовой форме `/` и в Studio `/launch.html` есть «Загрузить через Pons».
Backend сначала проверяет MIME, байты, декодирование, квадратность и размер.
Затем кратковременно запускает отдельный Chromium, открывает страницу Pons и
выбирает файл в её обычном file input. Контекст новый, без расширений и кошельков.
Изменяется только локальное поле имени, чтобы убедиться, что React уже готов;
кнопки продолжения/запуска токена не нажимаются. После ответа браузер закрывается.

Ждём не просто появления HTML file input: он бывает доступен до подключения
обработчиков React. Готовность проверяется сохранением тестового имени в локальный
черновик Pons. Повтор этой локальной проверки ограничен; сам upload не повторяется.

Ссылка валидируется, CID сверяется с URI, исходный файл читается обратно через
content endpoint, который использует текущий frontend Pons:
`https://dbk-vercel.vercel.app/api/ipfs/content/<cid>`.
Чтение ограничено таймаутом/размером, байты сравниваются с исходными. При задержке
gateway успешный URI всё равно возвращается с verified=false и предупреждением;
не нужно публиковать тот же файл повторно. Это не гарантия вечного pinning.

Сохраняется ipfs:// в черновике; после reload он остаётся. Ошибка загрузки
не меняет предыдущую ссылку. В Studio на время загрузки блокируются создание,
смена проекта и новый черновик. Параллельный upload в одном процессе отклоняется.
Маршрут доступен только с локальной панели с совпадающим Origin; сайты токенов
на *.localhost не могут использовать upload endpoint Studio.

Для локальной установки нужны npm dependencies и Chromium:

```text
npm ci
npx playwright install chromium
npm run dev
```

На текущем компьютере Chromium уже установлен. Это помощник локальной панели;
никакой браузер/хранилище на VPS не разворачивались. Playwright1.63.0 закреплён
как runtime dependency. Переезд панели на сервер — отдельная задача.
Если Pons изменит форму/ограничения, helper остановится с ошибкой; доступен
готовый ipfs:// URI и ссылка на оригинальную форму. Ручное извлечение ссылки
из своего черновика Pons: DevTools → Application → Local Storage →
`pons-launch-draft:v1` → поле `image` (без экспорта остальных данных).
