# Конструктор запусков: актуальные границы

Уточнение владельца 10.10.2026. Приоритет над ранними примерами PLATFORM_START
и историческими «следующими шагами» отдельных пакетов.

## Что создаём

Личный лаунчпад поверх Pons: владелец из локального UI задаёт параметры токена
и собственных механик распределения полученных комиссий, проверяет план,
подписывает запуск и получает обслуживаемый проект со страницей на поддомене.
Новый токен не должен требовать разработки отдельного приложения или копии бэка.
Розыгрыши — первая механика расширяемой платформы, не единственное её назначение.

Две равноправные задачи: гибкая экономика и общая инфраструктура. Код и серверные
ресурсы общие, контракты, средства, билеты, RNG-контекст, состояние и журналы
изолированы по токенам. QIANQI уже обслуживается адаптером платформы;
это не означает готовность всех механик для создания новых экземпляров.

## Программа розыгрышей

- Short — настраиваемый короткий цикл, вплоть до 7 суток (604800 секунд).
  Он не ограничен ежедневным режимом. Нижняя продуктовая граница пока не уточнена.
- Monthly остаётся отдельной месячной механикой QIANQI, не Short с большим интервалом.
  Ранее использовался пресет 30 суток; различие календарного месяца и 30 суток
  новым уточнением не разрешено. Не выбирать другую семантику молча.
- Режимы при создании: Short, Monthly, оба. Базовый Pons без надстройки — отдельный путь.
- Настраиваются покупательский порог билета, доли призы/команда/обслуживание,
  минимальные фонды, число призовых мест и распределение призов в пределах
  реализованного алгоритма. Значения 80/15/5, 10 USDG, 50 USDG, 24 часа и один
  слот принадлежат первому тестовому профилю, а не всей платформе.
- Изменение правил уже запущенного токена — отдельное решение; гибкость конструктора
  сама по себе его не разрешает. Frozen циклы неизменны.

## Фактическое состояние на 846ae77

| Возможность | Состояние |
|---|---|
| Настройки Short/Monthly, split, билет, фонды и корзина | Есть модель, редактор и валидация |
| Верхняя граница Short в неделю, фиксированная месячная семантика | Решение записано; текущий общий валидатор ещё допускает произвольные интервалы |
| Запуск и сквозное исполнение новых токенов | Реализован Short/USDG, проверен локально |
| Monthly для новых токенов | Не подключён: validateLaunch явно запрещает monthly.enabled |
| Число победителей Monthly | Общая модель пока допускает только одного; расширение не реализовано |
| Monthly существующего QIANQI | Сохранён в отдельном адаптере; не универсальный deployment нового токена |
| Общий сервер и API | Используются QIANQI; новый Short runtime пока проверен локально |
| Страница нового токена и handoff из owner UI | Проверены локально; серверное подключение впереди |

Нельзя обозначать весь конструктор готовым по результатам одного Short-профиля.
Нельзя включать настройки в UI как исполняемые, если deployment/worker их не поддерживают.

## Следующий согласуемый пакет

распределение призовой доли между Short/Monthly, текущий/следующий месячные резервы,
независимый lifecycle билетов, RNG и поздние подтверждения. Отдельно перечислить
уже принятые правила и действительно открытые решения, не изобретая новые по умолчанию.
После согласования — перенос Monthly, соединение конфигуратора с deployment/runtime
и три сквозные репетиции (Short, Monthly, оба) на разных токенах общего бэка.
Серверное подключение и первый публичный запуск не заменяют этот объём платформы.
