## Приоритетные находки и доработки (до пяти)

### F1. P2 — **подтверждённая неоднозначность легенды**: «равно» и «сравнить нельзя» слиты в одну подпись

**Код:** [`apps/monitor/tokens.js`, строки 78–87](../apps/monitor/tokens.js); [`apps/monitor/ui.js`, ключ `chartNeutral`](../apps/monitor/ui.js); [`apps/monitor/ui.css`, `.trend-bar`](../apps/monitor/ui.css).

**Воспроизводимо логикой:** `direction` принимает `up`, `down`, `flat`, `unknown`; для полного интервала без полного предшественника будет `unknown`. Но aria-label/title строится так, что и `flat`, и `unknown` получают `t('chartNeutral')` — «Unchanged / no comparison» / «不变 / 无法比较» / «Без изменений / нет сравнения». Фактические числа **5 и 5** отличаются по смыслу от **5 и неизвестно**. Первый из 7 интервалов всегда не имеет предыдущего в отображаемом наборе. Объединение опасно и для чтения без цвета/скринридером. При этом неполное значение дополнительно помечено `trend-gap` — проблема особенно касается **полного текущего окна при отсутствующем предыдущем**.

**Минимальная правка:** отдельные термины `unchanged` и `previous-window-unavailable` с EN/zh/RU локалями; для `unknown` явная подпись отсутствия сравнения и иной shape/marker/legend entry, не только серый/цвет. Оставить точный смысл «высота=count, цвет=дельта к предыдущей пятиминутке». Тест: два полных окна с одинаковым значением, полный текущий при previous partial/missing, первое окно — разные `aria-label` и читаемая легенда.

### F2. P2/3 — **обоснованный риск наложения чисел на mobile**, требует настоящего visual fixture

**Код:** [`apps/monitor/ui.css`, последние правила `.trend-value` и `@media(max-width:700px) .trend-plot`](../apps/monitor/ui.css), [`apps/monitor/tokens.js`, строки 74–95](../apps/monitor/tokens.js).

`.trend-plot` на телефоне размещает 7 столбцов через `repeat(7,minmax(0,1fr))` внутри 320px viewport, `.trend-value` центрируется через `left:50%; transform:translateX(-50%)`, но имеет `width:max-content`. Для `10,000` / `100,000` / `1,000,000` текст потенциально **шире своей колонки** (соседние подписи налезут друг на друга), хотя проходящий browser-тест использует в основном небольшие значения. Это прогноз из CSS/DOM, **не доказанная фактическая коллизия на screenshot**.

**Минимальная правка после подтверждения:** в ограниченном viewport выводить над барами компактный label (`10k`, `1.2m`) **только как визуальное сокращение**, полный count оставить в `aria-label` и selected summary; либо в mobile скрыть маленькие labels на неселектированных барах, сохраняя full count по tap/keyboard. Тест fixture с последовательными семизначными значениями на 320/390 во всех языках, bounding boxes соседних label не пересекаются, 7 touch targets и горизонтальный overflow отсутствует.

### F3. P3 — **реальная недолокализация денежных сумм на RU**

**Код:** [`apps/monitor/ui.js`, `amount()` в строках 130–135](../apps/monitor/ui.js), использование в [`tokens.js`](../apps/monitor/tokens.js) и [`wallet-ui.js`](../apps/monitor/wallet-ui.js).

`U.num` использует `toLocaleString(locale())`, но `U.amount` для валидных десятичных строк всегда вручную группирует по `,` и ставит десятичную `.`, вне зависимости от выбранной локали. Например `1234.5 ETH` в RU останется `1,234.5 ETH` вместо ожидаемого `1 234,5 ETH`, в то время как `buyers/buys` и даты используют RU. В EN/zh похожая пунктуация естественна, в RU это **непоследовательность реального кода**. Нельзя просто перевести всё через Number: теряется точность больших/малых onchain строк.

**Минимальная правка:** оставить bigint/string decimal arithmetic для округления, локализовать **только separators/grouping** по `locale()` (или безопасно разбить на integer/fraction и определить delimiters через `Intl.NumberFormat(locale()).formatToParts`), не менять units ETH/USDG и не делать £/¥ конверсию. Тест: ``0.00000001 ETH``, ``1234.567890123456789 ETH``, ``9007199254740993.001`` по EN/zh/RU и переключение языка без запроса сети.

### F4. P3 / UX — **не путать среднее перед latest и сравнение выбранного раннего окна**

**Код:** [`apps/monitor/tokens.js`, строки 42–57, 66–99](../apps/monitor/tokens.js), [`ui.js`, ключ `chartMeanLegend`](../apps/monitor/ui.js).

Пунктир рисуется через `comparisonFor(latest,k,intervals)`: это **шесть окон, предшествующих latest**. При выборе раннего бара `heatDetail(d,k,intervals)` считает уже **шесть окон перед выбранным**. В наборе всего 7 окон такой полной базы у ранних баров нет, и summary корректно пишет, что сравнение недоступно. Арифметического дефекта здесь **нет**, но пользователь видит пунктир, выбирает ранний интервал и в summary получает «нет сравнения» — без уточнения может показаться ошибкой графика.

**Минимальное оформление:** оставить пунктир **явно подписанным как среднее перед последней пятиминуткой** во всех языках, а в summary раннего окна написать «Для выбранного раннего окна в доступных данных нет шести предыдущих полных интервалов». Не добавлять историю/ещё графики ради этого. Тест: latest +6 полных (есть baseline), selected earlier (baseline в summary отсутствует, линия остаётся только latest), last gap (baseline ни там, ни там); сравнение не рисуется при неполном окне.

## Что выглядит правильно по коду

- Один язык `en/zh/ru` выбран в `U.set`; переподписи DOM и `languagechange` не инициируют Pons-запросов, данные/адрес фильтра сохраняются. RU добавлен владельцем и допустим в этой новой ревизии; не возвращаться к старому проектному ограничению «только EN/zh».
- `bar` — настоящий `button` со значением/временем/описанием в `aria-label`, `aria-pressed` на выбранной метрике/интервале; CSS даёт `:focus-visible`. Рисовать ещё одну интерактивную heatmap не нужно.
- `partial/stale/error/preview` имеют отдельные `data-note`, текущие нули отличаются от неизвестного `—`, неполные столбцы штрихуются, временные зоны: пользовательские часы для оси и MSK для исторического сравнения.
- Адреса не названы людьми. Для кошелька `positionsHelp`, `grouped` и две даты показывают пределы Pons. Ссылки Pons/X валидируются; пользовательский текст добавляется через `textContent`.
- Старые `.heat-grid/.heat-cell`, `.overview-page .cards` и прежние варианты текста остались в CSS/`ui.js`, но не создают DOM-дубликаты; передёргивать рефакторинг сейчас не стоит. После одобрения визуального вида допустима **нефинансовая уборка мёртвых стилей** под visual regression, без новых библиотек.
