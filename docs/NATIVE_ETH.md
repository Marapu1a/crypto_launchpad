# Две пары платформы: USDG и ETH

18.10.2026. По решению владельца платформа поддерживает два варианта: токен/USDG
и токен/ETH. Pattern Watcher готовится к ETH. Это новый локальный пакет поверх
checkout `a5cd33d`; существующие QIANQI/IGW и production не менялись.

## Контракт актива

| Вариант | Конфигурация | Точность | Pons pair | Получение комиссий |
| --- | --- | --- | --- | --- |
| USDG | v2, месячный IGW v3 | 6 | адрес USDG | escrow `claimToken(address)` |
| ETH | v4, с явным schedule для месячного IGW | 18 | zero address | escrow `claim()` |

В ETH-профиле нет фиктивного ERC20 по zero address и вызовов approve/transfer
к нему. Контракты принимают нативную стоимость через payable `fund(amount)`;
`msg.value` обязан совпадать с amount. Получателю отправляется ETH, без WETH.
Баланс фонда и баланс газового кошелька исполнителя изолированы.

Источник: [Pons v2](https://docs.ponsfamily.com/v2), проверено 18.10.2026:
native escrow `balanceOf(address)` / `claim()`, ERC20 `balanceOfToken` / `claimToken`;
`sweepFees(uint256)` переводит накопленные комиссии curve в escrow. Стартовая
покупка native включает ETH в transaction value вместе с launch fee.
Публичные контрактные вызовы и реальные переводы в этом пакете не выполнялись.

Дополнительно 18.10.2026, 12:43 UTC: публичные HTTP-ответы Pons для curve-токена
`0x597113bd319eb670e7cb662ad8149f68fa237e88` подтвердили native zero address,
ETH/18 decimals и `quoteAmount` в ETH. Две сделки прошли существующий нормализатор
без потери точности. Сырые ответы, URL, время и SHA-256:
`.local/research/native-eth-20261018T124348Z/` (основа `a5cd33d` + текущий пакет).
Всего четыре GET, включая первоначальный общий список graduated-токенов;
нет RPC, записи в рабочий журнал или утверждения тестового порога для PW.

## Реализация

- `src/draws/assets.mjs`: явные активы и decimals; денежные строки превращаются
  в bigint без float. USDG v2/v3 не принимают ETH; native использует отдельную v4.
- `contracts/production/native/`: collector, splitter, funding router, Short и
  прежний Monthly. Алгоритмы исходов сохранены; RNG-контекст native отделён.
  У месячного IGW остаётся Short-алгоритм с 30 сутками и явным schedule.
- `src/worker/native-build.mjs`: отдельный manifest. USDG-сборка не изменена:
  `0x2824a5d90a5160f42449e82ad770e57d68c9124dbf99177da396b74dd853f640`.
  Native: `0x278b4f1610ef08160374c1cb46a03d47361bb079cf7fb1711d2c8ffb9c2205bb`.
- Owner coordinator выбирает сборку по активу; форма показывает обе пары,
  очищает суммы при смене валюты и сохраняет выбранный актив при восстановлении.
- ETH worker принимает только явный Pons-источник. Профиль отчёта должен
  содержать native quote/18 decimals и тот же порог, что и конфигурация.
  Покупки не восстанавливаются из изменения ETH-баланса или газовых расходов.
- API и общая публичная страница проекта используют актив/точность конфигурации.
  Старый v1-редактор и USDG fork-скрипты остаются legacy-инструментами.
- Отказ native-получателя проверяется симуляцией до создания подписанного намерения:
  долг остаётся в контракте, остальные выплаты продолжаются. После завершения
  другой работы повтор через час либо при новом событии Pons; ожидание не опрашивает RPC.
  Ошибки транспорта/платёжеспособности не маскируются под отказ получателя.
  Если поведение получателя изменится уже после симуляции и подписанная операция
  откатится, сохраняется прежнее правило журнала: остановка до сверки оператором.

## Проверка и границы

Локальные тесты: `tests/unit/native-assets.test.mjs`,
`tests/contracts/native-draws.mjs`,
`tests/contracts/pons-draw-worker-cycle.mjs --native`,
`tests/studio/owner-production.mjs`. Отчёты в `.local/test-results/`.
Сборка артефактов: `npm run build:native-programs`. `--direct` у worker-теста
проверяет общий worker без HTTP/RPC-budget оболочки; обычный `--native` — с ней.
В контрактных тестах смоделированы Pons/chain 4663; для RNG — сохранённый BLS-вектор.
Ограниченная HTTP-проверка выше не заменяет полную репетицию live-интеграции,
не доказывает будущую доступность API или секретность будущего seed.

Native fee splitter сохраняет назначение старых lanes: prizes/team/operations.
Он **не является** holder vault 60/20/20. Подключение [holder ledger](HOLDER_LEDGER.md),
атомарный снимок держателей и платёжный журнал — следующий отдельный пакет.
Сервисные ETH-платежи также отдельны от торговых комиссий.

Для PW в [профиле](../tokens/PatternWatcher/preparation.json) выбран ETH/18;
билет, минимальный фонд, единица приза и минимальная выплата держателю пока `null`.
Не использовать числа из тестов или прежние 10/50/1 USDG как финансовое решение.
Перед реальным запуском нужны утверждённые суммы, отдельные deployment/profile
и полная репетиция запуска с выбранными параметрами. Публичный запуск не выполнен.
