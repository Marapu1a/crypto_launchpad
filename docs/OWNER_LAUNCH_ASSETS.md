# Адрес сайта и логотип в форме запуска

Решение владельца12.10.2026: пока запуск готовит оператор. Логотип согласовываем
заранее и кладём в проект; пользователь просматривает готовые данные.

- В production-форме вводится полный HTTPS-адрес сайта, например
  `https://igw.qianqi.site/` или адрес другого домена. Он сохраняется в
  `draft.website`, уходит в metadata Pons и используется handoff для планируемого
  hostname. Проверка занятости домена использует этот hostname. Внутренний slug
  проекта остаётся отдельным идентификатором, скрытым в production-форме.
- Для старых журналов без website сохраняется fallback `slug.baseDomain`.
  Новая production-форма требует website. Домен/DNS/TLS не создаются автоматически.
- Вместо IPFS-поля и загрузчика production-форма показывает путь исходного файла
  и его превью. Для IGW — `tokens/IGW/igw_logo.png`. По ссылке открывается именно
  подготовленная картинка. Выбор другого файла/публикация — часть подготовки
  оператором, не действие пользователя в форме. Репетиционный загрузчик сохранён.

## Подготовка оператором

После проверки и публикации логотипа добавить в приватный owner config:
`logoAsset: {path, uri, sha256}`. Path — файл PNG/JPEG/WebP внутри `tokens/<token>/`;
URI должен совпадать с `defaults.draft.logo`. SHA256 — хеш исходных байтов,
проверенных при публикации. Для IGW используется ранее опубликованный CID,
повторной публикации в этом пакете нет.

При старте сервер проверяет путь, реальное расположение файла, формат и хеш.
HTTP отдаёт только этот заранее выбранный файл; произвольный путь из запроса
не читается. Create с другим logo URI отклоняется. Путь файла не попадает в
контракт вместо IPFS: технический URI остаётся в подготовленных metadata.
