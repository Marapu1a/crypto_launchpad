# PW: защита общего RPC-бюджета

21.10.2026. Локальный пакет поверх `9dca991`; продолжение
[серверного preflight](PW_PREFLIGHT_20261021.md). Публикации этого пакета,
изменений финансовых параметров и активации PW не было.

## Поведение

1. Provider объединяет параллельные проверки сети и использует результат не более
   одной секунды. Ошибки не кешируются. Явный `send('eth_chainId')` всегда обращается
   к RPC; повторный `getNetwork()` после истечения секунды обнаруживает смену сети.
   Это не постоянный staticNetwork и не отключение проверки chainId.
2. PW operator и будущий PW runtime по умолчанию оставляют половину общего лимита
   нетронутой. При 2000/час PW отказывает, если операция оставит менее 1000 запросов.
   Основные адаптеры используют тот же файл и могут расходовать защищённый остаток.
   Это нижняя граница доступного остатка для PW, не отдельный кошелёк квоты и
   не гарантия, что остальные токены сами не исчерпают свои запросы.
   Переопределения: `rpcBudget.reserveRequests` у operator,
   `pwRpcReserveRequests` у общего host. Изменение счётчика/его схемы не требуется.
   Общая стартовая проверка host имеет приоритет и использует полный общий лимит;
   ограничение PW включается перед рабочим циклом. Иначе исчерпанная половина PW
   могла бы не дать запуститься QIANQI/IGW при доступном защищённом остатке.
3. При `RPC_BUDGET_EXHAUSTED` во время bootstrap общий runtime сохраняет host lock,
   закрывает созданные соединения, публикует причину и retryAt в health, затем
   ждёт конца окна. Ожидание прерывается SIGTERM. `once`/`failFast` сохраняют
   прежний отказ, чтобы диагностические команды не зависали.
4. Новый holder admission атомарно резервирует N+10 запросов: полный список,
   проверки блока перед commit и запас обнаружения сети. Чужой процесс не может
   забрать эту квоту посреди прохода. Внутри резерва нет двойного списания;
   неиспользованное не возвращается. Резерв нельзя перенести через границу окна.
   Если проход больше целого доступного окна, `RPC_OPERATION_TOO_LARGE` возникает
   до обращения к RPC. Если не хватает только текущего остатка — обычное ожидание
   обновления квоты. Частичный список не принимается, долги/история не меняются.

## Ограничения

- При 2000/час и reserve=1000 один новый проход допускает до **990 адресов**.
  Это предел текущего технического прохода, не ограничение числа холдеров токена.
  Для большего списка требуется отдельная возобновляемая проверка фиксированного
  блока. Автоматически повторять тот же заведомо слишком большой проход нельзя.
- RPC всё ещё нужен для финансового подтверждения. Pons остаётся источником
  активности и перечня адресов; его данные не превращаются в подтверждение выплат.
- Резерв не обеспечивает успех при сбое провайдера, reorg или устаревшем снимке.
  Отказ оставляет снимок непринятым. На границе окна незаконченный проход прекращается.
- Защищённый остаток действует только через новые PW gate. Старый процесс PW
  до обновления релиза продолжает прежнее поведение. Увеличения тарифа/квоты нет.
- Изменения общие для runtime/provider: выкатывать отдельным проверенным релизом,
  сохраняя существующие budget, journals, service identities и выключенное PW.
  Не редактировать файлы кода внутри действующих release.
