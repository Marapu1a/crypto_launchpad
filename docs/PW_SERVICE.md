# PW: сбор комиссий и месячный розыгрыш

19.10.2026. Отдельный адаптер `pw` общего Pons runtime. Регистрация сама по себе
не запускает службу и не разрешает реальные отправки. QIANQI/IGW сохраняют свои
адаптеры и контракты.

## Что обслуживается

- Билеты из полного накопленного отчёта Pons: каждые 0.001 ETH покупок дают билет.
  Историю нельзя заменять только последним окном монитора. Проверки покупок через
  сканирование блоков или traces не добавлены.
- Сбор комиссии из curve/escrow через PW collector. Только `forwardableFees`
  считается комиссией; случайные поступления ETH остаются в quarantine.
- Распределение 60% холдерам, 20% в draw, 20% проекту. У PW нет IGW fundingRouter:
  splitter перечисляет доли напрямую в соответствующие контракты.
- Один месячный Short draw по утверждённым правилам: первый срок через 30 дней
  от запуска токена, следующие — через 30 дней от завершения предыдущего.
  Минимальный фонд и единица приза 0.005 ETH. Один слот не гарантирует победителя.
- Подготовленная транзакция сохраняется до отправки. Повторный проход использует
  те же bytes/hash; подтверждённая операция не отправляется заново. Замороженные
  участники и случайность не заменяются при перезапуске или недоступности Pons.
- Подтверждённые receipts собственного журнала автоматически поступают в holder
  ledger: `Revenue` и доставка в vault. Cursor сохраняется после идемпотентного
  импорта; максимум 20 операций журнала за проход. Импорт повторяется после сбоя.

Начисление и выплата холдерам по-прежнему выполняются через
[PW operator](PW_OPERATOR.md): снимок, допуск, план, публикация, выплаты и сверка.
Этот пакет не включает автоматическую подпись holder-публикаций. Permissionless
операции, выполненные вне службы, восстанавливаются ограниченной командой
`holder-recover-funding`; известный receipt можно импортировать через `holder-funding`.
Перед новым планом сверяются revenue и holder deposits. Неполный receipt собственного
журнала не продвигает cursor. [Правила восстановления](PW_REVIEW_FIXES_20261019.md).

## Экономный режим

На очередном проходе читается локальный отчёт Pons. Неизменный состав торгов
после подтверждённого простоя не запускает RPC; обновление `checkedAt` не является
новой покупкой. Новые данные, срок готового draw или незавершённая операция
запускают рабочий проход. После перезапуска обязательства проверяются заново.
Недоступность источника не будит заведомо простаивающий токен до его срока.
Уже замороженный draw может завершиться без свежего источника; новый — нет.

Это не нулевой расход RPC вообще: рабочий проход проверяет привязки контрактов,
finality и receipts. Общий host применяет сохраняемый бюджет RPC и список
разрешённых хостов; QuickNode запрещён. Лимиты газа на транзакцию выбираются явно,
они не являются месячным бюджетом расходов.

## Регистрация после запуска

1. Завершить finalized launch и `handoff-register` для holder-программы.
2. В приватном operator config задать `serviceLimits`:
   `maxGasPrice`, `maxGasLimit`, `nativeFloor` — положительные строки в wei/gas.
3. Выполнить `service-handoff-preview`, затем `service-handoff-register`.
   Проверяются артефакты, исходный профиль, фактический launchAt, роли и split.
   Повторная регистрация допускается только с той же policy.
4. Сохранить полученный `policyHash` для конфигурации runtime. Результат
   `enabled:false` означает регистрацию без запуска daemon.

В существующем `pons-runtime-config-v1` добавляется запись проекта с полями:

```json
{
  "id": "<project UUID>",
  "adapter": "pw",
  "policyHash": "<hash from service-handoff-preview>",
  "rpcFile": "/absolute/private/rpc-url",
  "databaseFile": "/absolute/private/executor-dsn",
  "jobsDatabaseFile": "/absolute/private/jobs-dsn",
  "keyFile": "/absolute/private/encrypted-executor.json",
  "passwordFile": "/absolute/private/executor-password",
  "reportFile": "/absolute/state/pw-pons-accounting.json",
  "publicFile": "/absolute/public/pw-service.json"
}
```

Host: `scripts/run-pons-runtime.mjs`; обязательны отдельные `lockFile`,
`healthFile`, `rpcBudget`, режим и разрешённые RPC hosts. Для production нужен
отдельно разрешённый `allowPublicTransactions:true`; выключенная конфигурация
не активируется. Службе нужен только executor key, publisher для holder-операций
остаётся отдельным. DSN ролей `lp_executor`/`lp_jobs` не взаимозаменяемы.

`publicFile` содержит состояние службы и подготовленные снимки draw без private policy,
подписанных транзакций и секретов. Снимок может ещё ожидать freeze. Это техническая проекция; завершённые результаты
и пользовательский интерфейс запуска требуют отдельного оформления.
