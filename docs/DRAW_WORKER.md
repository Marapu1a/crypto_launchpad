# Исполнитель v2

Актуальное устройство 13.10.2026; реализация `server/shared/draw-worker.mjs`.
На сервере IGW включён отдельно; конфигурация службы не включается самим Git push.

## Последовательность

1. `draw-handoff.mjs` проверяет завершение/финальность owner launch и регистрирует
   проект, модуль и sender. Возвращает disabled-конфигурацию: домен и включение
   службы — отдельные шаги. HTTP owner UI имеет явный handoff route.
2. `draw-sender.mjs` держит lease на проект/sender, проверяет policy checksum,
   revision и binding перед сохранением. Executor и publisher изолированы.
3. `scanDrawHistory` обнаруживает события curve/token/recognition через getLogs,
   затем проверяет полные блоки и receipts обычным ledger scanner. По 5000 блоков
   за проход, запросы по 1000; полнота discovery зависит от доверенного RPC.
4. Планировщик чередует комиссии, recognition и активные draw-типы. Неизвестные
   покупки остаются в очереди и не получают неподтверждённых билетов.
5. Подпись сохраняется до отправки. Pending receipt ждёт финальности; повтор
   продолжает ту же операцию. Revert останавливает её для разбирательства.
6. Frozen участники, средства, RNG и расходование билетов отдельны для каждого
   типа. Поздние credits не переписывают snapshot. После proof/delivery/settle
   выполняются выплаты; результат сверяется с JS-расчётом.

Финансовые решения используют finalized-состояние. Упрощённое продвижение owner
по receipt не отменяет эту границу runtime. При pending-операции новый scan может
ждать её завершения; свежий public snapshot не означает нулевое отставание ledger.

## Служба

`server/short-runtime/start.mjs` читает отдельный config. `rpc-provider.mjs`
ограничивает primary/trace общей очередью 50 мс без batching. `runtime.mjs` изолирует
ошибки проектов, health не содержит сырых RPC errors/секретов. Public projection
показывает подтверждённые данные и состояние сервиса.

Недостаток ETH сохраняет ожидание; пополнение вручную. Существуют код уведомлений
и backup script, но наличие кода не означает их подключение для конкретного проекта.
