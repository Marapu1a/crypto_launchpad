# Обновление комиссии owner launch — 12.10.2026

Причина инцидента: зарезервированный gasPrice20184000 оказался ниже текущей
baseFee. Оба RPC отвергли симуляцию с `max fee per gas less than block base fee`;
тот же вызов с увеличенной ценой успешно симулировался. По двум RPC хеш
0x2954b420fc098febf911af8b7d6362d97f96658dad8f0bb992e7ff922304288b отсутствовал,
latest/pending nonce30, баланс не изменился. Это объясняет непригодность старой
комиссии, но не доказывает внутреннюю причину первого Smart Transaction timeout.

Исправление: новая цена — 2×max(RPC gasPrice, latest baseFee); при восстановлении
не менее113% предыдущей цены. Это legacy gasPrice, фактически оплачиваемая цена,
а не EIP-1559 ceiling. UI объясняет запас; лимиты профиля не увеличиваются.

Отдельное действие reprice не подписывает и не отправляет транзакцию. Оно сохраняет
nonce/from/to/data/value/chainId и ID операции, симулирует запрос с новой ценой,
не уменьшает gasLimit, проверяет лимиты цены/газа/общего бюджета и баланс.
Latest/pending nonce проверяются до и после симуляции. Старый запрос сохраняется
в feeRevisions серверного журнала. Известный hash запрещает reprice.

Повтор подписи отдельно проверяет revision, nonce, baseFee и оставшийся бюджет.
Если старая отправка всё-таки появится, она может быть присоединена: исходное
действие и nonce те же, старые пределы не превышают новых. Два исполнения с одним
nonce невозможны в одной канонической цепочке. Отсутствие хеша в RPC само по себе
не считается доказательством невозможности поздней доставки.
