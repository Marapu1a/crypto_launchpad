# Crypto Launchpad

Собственный конструктор запуска токенов через Pons: форма, чтение условий сети,
симуляции и запуск на локальном fork. Надстройка розыгрышей развивается отдельно;
покрытие базовой интеграции Pons пока неполное.

Сквозной локальный запуск токена с розыгрышем уже доступен отдельным стендом:
`npm run build`, затем `npm run studio` → http://127.0.0.1:4185/launch.html.
Создание, PostgreSQL worker и localhost-сайт соединены; реальные deploy пока
не включены. [Условия, результаты и границы](../../NEW_TOKEN_STUDIO.md).

Актуальный конструктор Short/Monthly v2: `npm run owner:draw-rehearsal` →
http://127.0.0.1:4188/owner.html. [Возможности и ограничения](../../DRAW_OWNER_UI.md),
[полный цикл токена владельца](../../OWNER_DRAW_CYCLE.md),
[путь к первому реальному запуску](../reports/FIRST_REAL_TOKEN.md).
Это отдельный частный стенд; не запускайте второй поверх уже работающего.

Подготовлен [production-профиль первого запуска](../reports/OWNER_PRODUCTION_PREPARATION.md)
с выключенными подписями; установка обслуживания на VPS ещё впереди.

## Открыть приложение

```powershell
npm ci --ignore-scripts
npm run dev
```

Адрес: http://127.0.0.1:5173. По умолчанию — чтение основной сети и симуляции.
Картинке пока нужен готовый IPFS URI; выбранный файл даёт локальный preview.

Для тестового запуска во втором терминале:

```powershell
npm run fork
```

Выберите в приложении `Local fork · тест`, затем «Подключить кошелёк» — будет
выбран тестовый аккаунт Hardhat. Заполните форму и выполните проверку запуска.
Approve и запуск доступны только на localhost chain 31337 с fork сети 4663.
После успешных тестовых отправок можно начать новый черновик: прежний сохраняется
в локальном архиве; JSON export позволяет забрать результаты отдельным файлом.

Публичный RPC хранит доступное состояние недолго: если fork перестал работать,
сохраните результат, остановите `npm run fork` и запустите заново. Старые локальные
токены после этого отсутствуют; создайте новый черновик. Для устойчивого стенда
запишите URL archive endpoint одной строкой в `.local/config/pons-rpc.txt`.
Файл исключён из Git и недоступен через dev server. `npm run fork` прочитает его
автоматически; `PONS_ARCHIVE_RPC` в окружении имеет приоритет. Пустой файл означает
публичный RPC. После изменения URL перезапустите fork. Поддержка исторического
состояния конкретным endpoint проверяется отдельно.

## Проверки

Node.js 22 или новее, npm:

```powershell
npm ci --ignore-scripts
npm test
npm run check:rpc
npm run build
npm run test:fork
npm run test:ui
```

Fork- и UI-тестам нужен уже запущенный `npm run fork`. UI-тесты запускают dev
server автоматически, если он ещё не работает. Отчёты и screenshots —
`.local/test-results/`. Отдельная проверка импортированной базы:

```powershell
npm run check:upstream
npm run test:reference
```

Последняя команда запускает только выбранные офлайн-тесты исходного QIANQI,
а не проверку готовности платформы. Копия для прогона и результаты остаются
в `.local/reference-tests/`. Сеть, кошельки и production-конфиги не требуются.

Черновики — `.local/drafts/`, напоминалки — `.local/notes/`, логи — `.local/logs/`.
Вся `.local/` исключена из Git. Согласованные решения переносим в `docs/`.

Новый проект не зависит от расположения исходной репы на компьютере.

Валидация формы и Node API описаны в [VALIDATION](../../VALIDATION.md).
Для локального просмотра собранной версии: `npm run build`, затем `npm start`
(http://127.0.0.1:4173). Статический хостинг без API не поддерживает подготовку запуска.
