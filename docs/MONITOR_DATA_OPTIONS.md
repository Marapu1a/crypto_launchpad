источника production. Существующие изменения оплаты и фронта сохранены.

## Варианты и границы

### Уточнение полей Pons, 20.10.2026, 15:28 МСК

Снимки `.local/pons-wallet-fields-20261020T122832Z/`; исследованы три адреса:
`0x235602316ff723f044924985f5d5ef8f6e3cc0a3`,
`0xa7485ef87163a2698fad45db3767268f4a04be97` и owner.
Identities/card/positions ответили HTTP 200. Positions содержит соответственно
150/9/2 строки, available=true/pending=false. Ранее были 503: стабильность
не доказана. Для 150 строк лимит/полнота не установлены.

- Identity: username, displayName, avatarUrl, bannerUrl, description, joinedAt;
  у одного адреса null — это отсутствие профиля, не отсутствие сделок.
- Positions: amountTokens/valueUsd, state=open/closed, buys/sells,
  investedUsd, realizedPnlUsd/unrealizedPnlUsd/totalPnlUsd/totalPnlPct,
  firstTradeAt/lastTradeAt, reliable; часть строк содержит buyTimes,
  transferTimes, receivedUsd. Есть totals, available, pending, updatedAt.
- Встречаются receivedUsd>0 при buys=0, а также reliable=false с нулевой
  оценкой USD. Поэтому количество позиций нельзя автоматически считать
  количеством купленных токенов, а нулевую оценку — отсутствием ценности.
- Два списка trades по токенам вернули side/trader/quoteAmount/tokenAmount/
  price/timestamp/txHash/id/venue. Dollar amount в строках не обнаружен.
  Метаданные launch дают quote.address/symbol/decimals и quoteUsd.

Для топа за интервал: число покупок, объём в валюте пары, медиана, максимальная
покупка и доля ведущего токена вычисляются из наблюдаемых сделок. USD можно
показывать как оценку по зафиксированному курсу quoteUsd со временем курса;
это не доказанная долларовая стоимость в момент сделки. Разные валюты
складывать только после явного пересчёта; неизвестные оценки не заменять нулями.
investedUsd/buys/sells из positions не являются метриками выбранного интервала.
Значение investedUsd и алгоритм PnL не проверены, не выдавать их за точный
оборот, денежный поток или доходность за всё время.

Приоритет продукта уточнён владельцем: горячие кошельки по покупкам и объёму,
пересечение их токенов, концентрация доступных позиций. Полная лента
операций не является самостоятельной целью; эти результаты пока не меняют UI.

1. **Собственный архив уже получаемых сделок Pons.** Рекомендация для ближайшего
   пакета: до фильтров агрегирования сохранять покупки и продажи по адресу,
   токену и id события, с источником/интервалом покрытия. Текущий монитор
   сохраняет агрегаты и ограниченный кэш; кэш удаляет вышедшие из наблюдения
   токены, поэтому это ещё не долговременный архив сделок. Такой архив не требует
   дополнительных HTTP-запросов для уже собираемых страниц, но охватывает
   только наблюдаемые токены/периоды. Историю до начала сбора он не восстанавливает.
   Не менять метрики первого часа: архивировать сырьё отдельно, до buy/curve-фильтра.
2. **Pons wallet API.** Самый прямой путь к карточке произвольного адреса,
   но история блокируется, позиции нестабильны. Поддержка уже запрошена владельцем.
3. **PonsAPI community service.** [Документация](https://ponsapi.dev/docs)
   заявляет subscribeAccountTrade и сделки по токенам. История любого кошелька
   отдельным REST-методом не описана. Holders требует индексатор, выключенный
   по умолчанию. [Тарифы](https://ponsapi.dev/pricing) называют требование токена,
   а живая проверка gate сейчас его не требует. Документация расходится также
   по WebSocket-лимитам. Это независимый от Pons Labs сервис, не доказанный
   резерв. Следующий эксперимент — отдельный пустой исследовательский кошелёк
   для login-only подписи, затем read-only сравнение данных; рабочие ключи не нужны.
4. **Обозреватель.** [Blockscout API](https://docs.blockscout.com/devs/apis)
   потенциально даёт transfers/балансы. Наши пробы 403: рабочего резерва пока нет.
   Перевод не равен покупке; для классификации нужны события сделки/receipt.
   [Etherscan Robinhood](https://robin.etherscan.io/api) — ещё один кандидат,
   но бесплатность этой сети и работа с ключом в этой проверке не подтверждены.
5. **RPC по запросу.** Уже настроенный Alchemy можно использовать в отдельном
   ограниченном бюджете для native balance, balanceOf известных токенов и
   receipt известных транзакций. Обычный RPC не предоставляет готовый список
   всех токенов/всех операций кошелька. Полная история потребует индексатора
   или сканирования; это отдельный объём, не включать молча.

## Предложение

Сначала архивировать уже собранные сделки, показывая точный охват и пробелы.
Затем проверить независимый read-only поток PonsAPI и доступный обозреватель.
Не обещать полный портфель, исторический PnL или историю любого адреса до
проверки покрытия. Оплата остаётся выключенной: этот документ не меняет
[условия запуска подписки](MONITOR_SUBSCRIPTIONS.md).
