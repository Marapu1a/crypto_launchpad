# Месячные периоды, внешние выплаты и восстановление

18.10.2026. Продолжение [журнала исполнения](HOLDER_EXECUTION.md).
Локальная реализация поверх `2b5d3d1` и текущего рабочего пакета; без deployment,
реальных транзакций и изменений существующих QIANQI/IGW.

## Следующий период

`advanceHolderPeriod(jobsPool, executorPool, scope, {provider, period})`:

- Проверяет журнал исполнения и находит единственный успешный finalized seal
  для сохранённого плана. Неполная публикация не завершает период.
- Под блокировкой preparation повторно проверяет receipt, каноничность блока
  снимка и связь с admission. Фиксирует событие `round.finalized` один раз.
- Общее добавление событий не принимает `round.finalized`: нужен trusted importer.
- Следующий admission использует следующий 30-дневный интервал от launchAt.
  Не нужно ждать, пока все держатели заберут прошлые начисления.
- Уже распределённые суммы исключаются из доступного бюджета навсегда;
  округлённый остаток остаётся доступным. Продажа токена не гасит старый долг.

`availableForAllocation` в preparation — доставленные средства минус завершённые
начисления. Он не учитывает ещё открытую публикацию; перед новым планом обязательно
проверяется on-chain available/pendingBudget. Старый `ledger` имеет явную метку
`funding-and-fixtures-only` и не является учётом реальных выплат.
`existingDebt`/`totalDebt` в preview наблюдаемого профиля равны null, а не ложному нулю:
действительный общий долг возвращает `reconcileHolderExecution`.

Для PW утверждена и реализована [политика первого принятого снимка и переноса](PW_LAUNCH_RECOVERY_20261019.md):
календарные периоды можно пропустить, средства остаются в фонде. Принятый список
не заменяется даже при задержке публикации. Старые профили без schedulePolicy
сохраняют прежние строгие окна.

## Прямые выплаты

Контракт разрешает любому оплатить газ за выплату исходному получателю.
`importExternalHolderPayments` принимает только хеш транзакции, самостоятельно
проверяет finalized receipt, pinned runtime/привязки и события Paid от своего vault.
Импортируются все выплаты этого vault в транзакции (до 100), в том числе через
контракт-посредник. Переданные пользователем суммы/адреса не принимаются как факт.

Миграция 018 добавляет отдельную неизменяемую таблицу под RLS, доступную executor.
Повторный импорт сверяет доказательство; изменение блока вызывает ошибку.
Внутренняя транзакция не может импортироваться как внешняя и наоборот.
Общая сверка заново проверяет обе группы и сравнивает сумму с totalPaid.
Без импорта прямой выплаты расхождение останавливает сверку, после импорта
обязательства сходятся. Бюджет проверки ограничивает суммарное число транзакций.

Импорт известного хеша дополнен [ограниченным сканером Paid](PW_LOCAL_REHEARSAL.md)
с сохранённым cursor. Он запускается по запросу, без постоянного опроса цепи.

## Что возможно при сбое

`inspectHolderRecovery` — read-only диагностика: checkpoint, адрес publisher,
позиции публикации и хеши неизвестных транзакций. Подписанные байты в отчёт
не выводятся; новых полномочий эта функция не даёт.

| Ситуация | Доступное действие |
| --- | --- |
| Процесс упал до отправки | Загрузить сохранённые подписанные байты |
| Ответ после отправки потерян | Проверить тот же хеш; не создавать новую выплату |
| Список опубликован частично | Сверить префикс и продолжить тот же план с указанного offset |
| Получатель отклонил ETH | Долг остаётся; повтор после исправления причины |
| Publisher временно недоступен | Завершённые начисления можно забрать без него |
| Ключ publisher потерян | В v1 смены роли нет; в managed v2 владелец может заменить publisher на паузе |
| Ошибочный префикс уже записан | Проверка остановит продолжение; отмены/замены списка нет |

Для прежнего vault v1 publisher immutable. Для PW добавлен managed vault v2:
[минимальное управление](HOLDER_GOVERNANCE.md). Владелец ставит публикации на паузу,
меняет publisher и возобновляет тот же корректный список. Завершённые долги и
выплаты доступны во время паузы. Диагностика показывает текущие роли на finalized
блоке. Автоматических управляющих транзакций и реальных ключей в пакете нет.

## Проверка и дальнейшая работа

`npm run test:holder-execution` теперь включает два периода с изменившимся составом
держателей, сохранением долга продавшего токен кошелька, остатком округления,
маленькими начислениями ниже порога, прямой выплатой через стороннего спонсора,
повтором импорта и проверкой восстановления частичной публикации.
Отчёты сохраняются отдельно в `.local/test-results/holder-execution-*/report.json`.

выплачено 60, непогашенный долг 10, свободно 50. Остаток включает 1 единицу
округления второго периода и 49 нераспределённых единиц. Проверены диагностика
неизвестной транзакции без раскрытия raw bytes и продолжение публикации с offset 1.
