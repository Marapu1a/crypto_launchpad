# Monthly: контрактный цикл и резервы

10.10.2026, база72a31f5. Следующий пакет [DUAL_DRAW_PLAN](DUAL_DRAW_PLAN.md).
Новые файлы отдельно от существующего Short; никаких production-отправок.

## Реализация

`contracts/production/MonthlyProgram.sol` — кандидат для chain4663. Принимает
уже выделенную МЕСЯЧНУЮ долю, не весь доход токена. Внутри распределяет Current/Next
как2:1 с переносом raw-остатка между поступлениями; Next ограничен nextTarget.
После заполнения Next все его новые поступления идут в Current.
Настраиваются minimumFund и nextTarget; интервал всегда30суток, один призовой слот.

Freeze допускается после30суток от последнего settle (первый отсчёт от deployment),
с непустыми участниками, достаточным Current и полным Next. Замораживается весь
Current. Новые fund-поступления после freeze не изменяют приз и участников.
Контракт проверяет структуру и порядок checkpoints; достоверность покупок,
полнота набора, каноничность/finality остаются обязанностью будущего worker.

`MonthlyOutcome.sol` переносит QIANQI V2: общий gate75/25 и один взвешенный
выбор по floor(2^128*x/(x+1)). JS `src/draws/monthly-outcome.mjs` независимо
вычисляет результат. Алгоритм gate/selection совпадает с QIANQI, но context
и resultHash имеют новый домен экземпляра, не имитируют его старые hashes.

При выигрыше frozen Current резервируется для claim, Next переводится в Current
и обнуляется. При отсутствии победителя бюджет возвращается в Current, Next
сохраняется. В обоих случаях frozen попытки расходуются, таймер обновляется.
Новые поступления вновь наполняют Next; обязательства прошлых выплат недоступны
для новых фондов. claim может вызвать любой, но получатель всегда зафиксированный
победитель. Нет ручного вывода, reset/reroll или override seed.

У каждого экземпляра отдельный существующий ShortDrandAdapter: его имя историческое,
но интерфейс обслуживает одного фиксированного consumer. Monthly создаёт свой
adapter и принимает fulfill только от него. Старый Short adapter не перенастраивается.
Одному frozen context соответствует один request/round; доказательство и callback
разделены, повтор callback не меняет результат.

## Пределы пакета

- Общий маршрутизатор Short/Monthly ещё не реализован. Существующий FeeSplitter
  способен работать через fund-interface, но соединение полной v2 deployment-схемы
  не проверено. Нельзя направлять весь призовой доход прямо сюда для режима «оба».
- Worker, ledger двух типов, owner UI, публичная проекция Monthly и серверная
  активация не подключены. Нельзя запускать этот кандидат прежним Short-планом.
- compileProduction по умолчанию не включает новые файлы: прежний manifest/hash
  `0x24fe240da110404159ec3b3695b4b4c1dd6a312f4dabf60e261f7880207c9ad1` сохранён.
  Новый кандидат компилируется явно тестом; версионированный deployment build впереди.
- Учитываются поступления через fund(amount). Прямой ERC20 transfer без fund
  увеличит фактический баланс, но не призовые счётчики; автопризнания surplus,
  как syncUSDG в старом QIANQI, здесь нет. UI/collector должны использовать fund.
- Операции над максимумом1000участников ещё не оценены по боевому gas-бюджету.
  Финальность в локальном тесте не равна проверке реального консенсуса.

## Проверки

`npm run test:monthly-contracts`: 4 сценария PASS.

1. Параметры,30суток, minimumFund/Next, запрет чужого freeze/fulfill.
2. Настоящий MonthlyProgram: историческая BLS подпись → фиксированный round →
   deliver → settle, независимый resultHash; неверная подпись/подмена snapshot/
   повтор settle отклоняются, другой экземпляр не меняется.
3. 24 набора context/seed с двумя неравными весами: Solidity и независимый JS
   совпадают с сохранённым reference QIANQI; покрыты обе ветки gate.
4. Test-only наследник принудительно выбирает seed для детерминированного покрытия:
   no-win, новый30-дневный интервал, win, перенос/повторное заполнение Next,
   дробные поступления, поздние деньги, consumed attempts и отсутствие двойного claim.
   В ABI настоящего MonthlyProgram testSeed отсутствует. Harness находится только
   в tests/contracts и не является deployable артефактом платформенного запуска.

8 unit/соседних PASS (Monthly input2, funding config4, drand2), размеры creation/runtime
проверены против EVM limits. Отчёт:
`.local/test-results/monthly-2026-10-10T19-02-31-504Z/report.json`.
Первый неудачный отчёт сохранён: тест пытался перевести время цепочки назад;
исправлен только расчёт времени теста. Готовность будущей случайности в настоящей
сети этот исторический BLS-прогон не доказывает.
