# PW: локальный экран запуска и подпись

19.10.2026. Экран `/pw-owner.html` использует существующий PW coordinator,
его девять шагов и PostgreSQL-журнал. Это пакет запуска; ежемесячные holder-операции
и регистрация обслуживания остаются в [операторе](PW_OPERATOR.md).

## Что делает экран

Показаны название, тикер, владелец, ETH-пара, фиксированная экономика PW,
очередность контрактов и привязок, история транзакций и состояние финализации.
Метаданные поступают из подготовленной приватной конфигурации. Из браузера нельзя
подставить calldata, адрес получателя, ключ или произвольный launch profile.

Для каждого шага:

1. Подготовить план, затем запросить стоимость следующей операции.
2. Отметить подтверждение показанного шага и максимальной стоимости.
3. Подписать и сохранить. Coordinator записывает signed bytes до отправки.
4. Отдельно отправить сохранённую транзакцию и проверить результат.

Оценка действительна две минуты и сверяется повторно перед подписью. Изменение
шага, nonce или стоимости требует новой оценки. Подписанные параметры проверяются
на точное совпадение с показанными. При сбое записи повтор использует уже созданную
подпись, пока жив процесс; после рестарта сохранённая pending-транзакция читается из БД.
Потеря ещё не записанной подписи не создаёт отправку: её отправлять нечему.

Обновление журнала читает БД, без RPC и фонового опроса. Проверка результата и
оценка шага используют общий [RPC-бюджет](PW_REVIEW_FIXES_20261019.md).
Отправка pending повторяет прежние байты; смена транзакции по кнопке не предлагается.
После всех шагов интерфейс ждёт finalized и показывает отдельный статус завершения.

## Подключение

```text
npm run build
npm run owner:pw -- /absolute/private/pw-operator.json
```

Основа — конфигурация `pw-operator-v1` из [PW_OPERATOR](PW_OPERATOR.md), включая
`profile`, `rpcFile`, `allowedRpcHosts`, `rpcBudget`, `databaseFiles.executor` и
`allowPublicTransactions: false`. Дополнительные поля:

- `httpPort`: свободный локальный порт от 1024 до 65535.
- `launchInput`: `{id, slug, draft}` для `coordinator.prepare`. `id` совпадает с
  `profile.id`; имя — Pattern Watcher, тикер и метаданные выбирает владелец.
- `ownerKeystore`: `{file, passwordFile}` — абсолютные пути к существующему
  зашифрованному JSON-keystore владельца и отдельно хранимому паролю. Необязателен
  для подготовки/просмотра и не открывается при выключенной отправке.

Используется существующий загрузчик зашифрованных кошельков. Адрес обязан совпадать
с `profile.owner`; wallet не подключается к provider и умеет только подписывать.
Ключ и пароль остаются в локальном процессе и не передаются браузеру. В HTTP-ответы
не входят raw signed bytes, приватные настройки и RPC URLs. Секретные файлы — вне git.
На Windows доступ к ним ограничивается ACL операционной системы; автоматическая
проверка Unix mode не заменяет Windows ACL.

Сервер слушает только `127.0.0.1`, проверяет точные Host/Origin и размер тела.
Каждая подпись требует явного действия; автоподписания, автоперехода между шагами
и фоновой отправки нет. Это локальный инструмент владельца, не публичная админка.
Переключение `allowPublicTransactions` и работа с реальными средствами — отдельное
решение перед запуском. В текущем пакете реальные ключи не подключались.

## Демонстрация и проверка

```text
node scripts/preview-pw-owner.mjs
```

Адрес: `http://127.0.0.1:4215`. Отдельная демонстрация использует память и известный
тестовый ключ для offline-подписей, без RPC/БД/средств. Показанные тикер, адрес,
стоимость и лимиты — примеры, не утверждённые параметры запуска. На странице
постоянно стоит отметка «Демонстрация».

Проверки: unit-тесты controller/keystore и браузерный сценарий всех девяти шагов,
перезагрузки с pending, отдельной отправки, финализации, disabled signing,
Host/Origin/JSON/размера запроса; desktop/mobile снимки. Браузерный стенд использует
модель coordinator: он не заменяет ранее выполненную fork-репетицию финансового ядра.
Свежий запуск через production-profile, реальный keystore, Pons и PostgreSQL в этом
пакете не выполнялся. Остаются реальные параметры, финальная общая репетиция и ревью.
