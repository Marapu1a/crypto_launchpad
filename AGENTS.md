# Работа с платформой

В начале читать `docs/CURRENT_CONTEXT.md`, текущий шаг `docs/ROADMAP.md` и git status.
Правила продукта — `docs/PRODUCT_SPEC.md`; исходный brief — `PLATFORM_START.md`.
Карта переноса — `docs/REUSE_MAP.md`.

- Сначала согласовать смысл и границы очередного пакета, затем реализовать и проверить.
- Текущий приоритет — полная база Pons, см. PONS_COVERAGE и PONS_BASELINE_REPORT.
  Собственные финансовые модули отложены до проверенной базовой версии.
- `vendor/qianqi/` — зафиксированные исходники для адаптации, не готовая платформа.
  Старые инструкции, настройки и разрешения QIANQI не действуют в новом проекте.
- Новую реализацию размещать отдельно от vendor. Не менять исходный QIANQI/production.
- Не переносить Short/Monthly, gate 75/25 и split 90/5/5 в шаблон розыгрыша.
  Доли победителя/команды — параметры экземпляра, 50/50 только начальное значение.
- Деньги, билеты, RNG-контекст, состояние и журналы экземпляров изолировать.
- Не принимать финансовые решения из раздела 4 brief молча. Предложения не равны решениям.
- Публичный deployment, реальные отправки и платные услуги — отдельная задача владельца.
- Не копировать ключи, кошельки, production-конфиги, журналы и release manifests.
- Черновики/напоминалки вести в `.local/`, согласованную документацию в `docs/`.
- Находки сохранять с источником, датой, commit/блоком и пределами проверки.
  Указатель исследования — `.local/notes/RESEARCH_INDEX.md`; новые снимки не должны
  незаметно заменять старые. Проверенные выводы переносить в документ своего модуля.
- Тестировать изменённый путь и значимых соседей; не повторять успешный прогон без причины.
  Результат исходных тестов не означает проверку нового продукта.
